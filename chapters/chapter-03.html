Manage Files from the Command Line

How to find your way around Linux, and how to create, copy, move, delete and link files using only the keyboard. Every idea comes with a picture and a small example you can type yourself.

🧭 How to use these notes
Read a section, then type the commands in the practice area below. Typing is how the commands stay in your memory. Lines starting with $ are commands you type (do not type the $). Lines without it are the output you should see.

🧪 Practice area (set this up first)

$ mkdir ~/practice $ cd ~/practice $ pwd /home/john/practice

Do all experiments inside ~/practice so you can never damage anything important. When you are completely finished: cd ~ first, then rm -r ~/practice. (You cannot delete a folder while you are standing inside it.) The username john is just an example; your own name will show up on your machine.

3.1 Describe Linux File System Hierarchy Concepts

Root directory structure

On Windows you have separate drives: C:, D:. Linux has no drive letters. Everything lives in one big upside-down tree. The very top of that tree is called the root directory and is written as a single slash: /

The Linux tree: one top, many branches. Every file on the computer sits somewhere on this tree.
  • The / character has two jobs: the name of the top directory, and the separator between names. So /etc/issue means: file issue, inside folder etc, inside the top /.
  • Each branch directly under / has a standard purpose, so every Linux system looks familiar.
❗ Do not mix these up
/ is the top of the whole tree. /root is the home folder of the administrator (the root user). Two different things.

3.3 Specify Files by Name

Absolute paths

A path is the address of a file or folder. An absolute path is the full address from the top. It always starts with / and works from anywhere, like a complete postal address.

# full address of a log file /var/log/messages # full address of a file in John's home /home/john/practice/notes.txt
💡 One-second rule
First character is / → absolute.

Relative paths

A relative path describes the route starting from where you are now (your current working directory). It never starts with /. It is like telling a friend in the same building, "second door on the left".

Standing in /home/john: the same place has two names, one long (absolute) and one short (relative).

Spaces in names

Linux allows spaces in a file name, but the shell uses spaces to separate words. So my file.txt looks like two names. Either put quotes around it, "my file.txt", or (better) avoid spaces and write my_file.txt.

Capital letters matter

  • Linux file systems (XFS, ext4) are case-sensitive: Notes.txt and notes.txt are two different files.
  • Windows-style file systems (NTFS, VFAT) keep your capitals but treat both spellings as the same file.

Path navigation

Your shell is always "standing" in one folder: the current working directory. After login it is your home folder. Print it with pwd (print working directory).

The two special names . and ..

Every folder contains two hidden entries: . means this folder and .. means the folder above. They are very handy: cp /etc/hostname . means "copy it to here".

The tilde ~ = my home

$ cd /var/log $ ls -l ~ # list my home, even though I'm in /var/log $ touch ~/hello.txt # create a file in my home from anywhere

Hidden files

  • A name that starts with a dot (.bashrc, .config) is hidden. See them with ls -a.
  • Hidden does not mean secret. It only keeps your home folder tidy. To really protect a file, use permissions.
📝 What does "tidy" mean?
Tidy means neat, clean and easy to read, with no mess. Your home folder has many small settings files, like .bashrc and .config. If ls showed all of them, your own documents would be lost in the clutter. So Linux hides them by default and your list stays short and clean.

But hiding is only for looks. Anyone can type ls -a and see them. A hidden file is not protected.

3.5 Manage Files with Command-line Tools

File operations

touch: create an empty file (or refresh its time)

If the file does not exist, touch creates an empty one. If it already exists, it only updates the "last modified" time.

$ touch todo.txt $ ls -l todo.txt -rw-r--r--. 1 john john 0 ... todo.txt (size 0) $ echo "buy milk" > note.txt # make a file WITH text in it $ cat note.txt buy milk

cp: copy

A copy is a second, independent file. If you edit one later, the other does not change.

FormMeaning
cp a.txt b.txtCopy a.txt to a new name b.txt
cp a.txt b.txt c.txt FolderCopy several files into Folder. The last word must be a folder
cp -r Folder1 Folder2Copy a whole folder with everything inside (recursive)
$ cp note.txt note_backup.txt $ cp -r school school_copy $ cp school/maths.txt . # the dot = "into this folder" $ cp school cp: -r not specified; omitting directory 'school'
  • Without -r, cp skips folders.
  • If a file with that name already exists, cp overwrites it without asking.

mv: move and rename (same command!)

In Linux, the full path is the file's name. So changing the folder part = moving, changing the last part = renaming. The content never changes.

$ mv note.txt shopping.txt # rename $ mv shopping.txt school/ # move into school $ mv -v school/shopping.txt . # move back, -v shows what happened renamed 'school/shopping.txt' -> './shopping.txt' $ mv school photos old_stuff # last name must be an existing folder
  • mv works on folders without -r.
  • It also overwrites silently. Add -i to be asked first.
  • On the same disk partition a move is instant (only the name changes). Between partitions it must copy the data and then delete the original.

rm: delete a file

$ rm todo.txt $ rm school rm: cannot remove 'school': Is a directory

Directory operations

mkdir: make folders

$ mkdir music $ mkdir music videos docs # several at once $ mkdir -p trip/day1 trip/day2 trip/day3 # -p also creates missing parents $ ls -R trip
  • mkdir a/b fails if a does not exist yet. -p builds the whole chain.
⚠️ The -p typo trap
You want a folder seen inside videos but type video.
mkdir video/seen → error (this protects you).
mkdir -p video/seen → no error; it quietly creates a brand-new wrong folder video. Use -p only when you are sure of the spelling.

Removing folders

CommandDoes
rmdir folderRemoves a folder only if it is empty (safe)
rm -r folderRemoves the folder and everything inside it
$ rmdir docs # works, docs is empty $ rmdir trip rmdir: failed to remove 'trip': Directory not empty $ rm -r trip # removes trip and its 3 subfolders

  • Be very careful with rm -rf combined with a wildcard or a variable. A mistake can wipe out much more than you meant.

3.7 Make Links Between Files

A link lets one file be reachable under more than one name or place, without copying it. Linux has two kinds: hard links and symbolic links (symlinks). To understand them, you first need to understand what a file really is. That is where the inode comes in.

Step 1: What is an inode? (the simple version)

📱 Phone contacts analogy
When you call "Mom" on your phone you do not memorise her number. Three things work together:
• the contact name "Mom" → the file name
• the phone entry with number, address, birthday → the inode (information about the file)
• the actual person who picks up → the data (the real content)

The name leads to the entry, and the entry leads to the person.

In Linux, every file is made of three separate pieces:

Name → Inode → Data. The inode is the middle layer.
  • Inode = "index node". It is a small record (a number plus details) that describes a file. It stores: file type, permissions, owner and group, size, timestamps, the link count (how many names the file has), where the data sits on disk, and the SELinux label.
  • The file name is not stored in the inode; it lives in the directory. The content is also not in the inode.
  • Because the name is separate from the file, one file can have several names. That single fact is what makes hard links possible.
  • Inode numbers are only unique inside one file system. (Two different partitions can both have an inode #12.)

See the inode yourself

$ cd ~/practice $ echo "Dear Sam" > letter.txt $ ls -i letter.txt # -i = show inode number 1049233 letter.txt $ stat letter.txt # everything the inode knows File: letter.txt Size: 9 Blocks: 8 IO Block: 4096 regular file Device: fd00h/64768d Inode: 1049233 Links: 1 Access: (0644/-rw-r--r--) Uid: ( 1000/ john) Gid: ( 1000/ john) Context: unconfined_u:object_r:user_home_t:s0 Access: 2026-10-21 20:10:11 Modify: 2026-10-21 20:10:11 Change: 2026-10-21 20:10:11 Birth: 2026-10-21 20:10:11

📝 Good to know: df -i and folder link counts
df -i shows how many inodes are used on each file system. A disk can run out of inodes while still having free space (for example, millions of tiny files). A folder's link count starts at 2 and goes up by 1 for each subfolder.

In simple words. Every file and every folder uses one inode. When a file system is made, it gets a fixed number of inodes. So a disk has two limits:
• space (how many bytes you can store): check with df -h
• inodes (how many files and folders you can have): check with df -i
$ df -i / Filesystem Inodes IUsed IFree IUse% Mounted on /dev/vda3 8910848 245120 8665728 3% /
IUsed = how many files and folders exist now. IFree = how many more you can create. If IFree is 0, you cannot create any new file, and you get "No space left on device", even if df -h shows lots of free space. This can happen with millions of tiny files (mail, cache). Fix: delete files you do not need.

Folder link count. A new empty folder shows 2: its own name in the parent, plus its own . entry. Each subfolder adds 1, because the subfolder's .. points back to it. Normal files inside do not change the count.
$ mkdir box ; ls -ld box drwxr-xr-x. 2 john john ... box (count 2) $ mkdir box/a box/b ; ls -ld box drwxr-xr-x. 4 john john ... box (count 4 = 2 + two subfolders)

Step 2: Hard links (a second name for the same file)

👤 Nickname analogy
Your friend Sam is called "Sam" by you and "Sammy" by his family. Two names, one person. If you stop using "Sam", the person still exists because "Sammy" still points to him. Only when every name is gone is nobody left.

When you create a file, it gets one name. The command ln adds another name that points to the same inode. Neither name is "the original"; they are equals.

Two names, one inode, one set of data. The link count shows 2.

Syntax: existing file first, new name second.

$ ln letter.txt letter-hard.txt $ ls -il letter.txt letter-hard.txt 1049233 -rw-r--r--. 2 john john 9 Oct 21 20:10 letter-hard.txt 1049233 -rw-r--r--. 2 john john 9 Oct 21 20:10 letter.txt
  • Same inode number (1049233) → it is the same file.
  • Link count 2 → two names point to it.
  • Both names share everything except the name itself: content, permissions, owner, times. Change permissions through one name and the other shows it too.

Deleting one name

$ rm letter.txt $ cat letter-hard.txt Dear Sam # the data is still safe $ ls -l letter-hard.txt -rw-r--r--. 1 john john 9 ... letter-hard.txt (count dropped to 1)

The data is only freed when the last name is removed (link count reaches 0).

Two limits of hard links

  1. Regular files only. No folders.
  2. Same file system only. An inode number only means something inside its own file system. Check with df: everything under / is usually one file system, but /boot is separate. A hard link between /boot/… and /home/… fails:
    ln: failed to create hard link '/home/john/x' => '/boot/y': Invalid cross-device link

Why is /boot a different file system? (if everything is under /)

Good question. Two different ideas are mixed here:

  • The tree is what you see: one set of folders that all start at /.
  • A file system is how one disk partition stores its files (XFS, ext4, vfat…). Each partition has its own file system, and its own inode numbers.

Linux builds the single tree by mounting. To mount means: "plug this partition into this folder". That folder is called a mount point. The folder /boot looks like any other folder, but behind it is a separate partition.

🏢 Building analogy
A building has one main entrance (/). Behind the door labelled "boot" is a separate storage room (another partition) with its own shelves and its own numbering. You walk in through the same entrance, but it is a different room. A hard link cannot reach across two rooms, because inode numbers belong to one room only.

A normal RHEL on a UEFI computer looks like this. Check yours with df -hT or lsblk -f:

$ df -hT Filesystem Type Size Used Avail Use% Mounted on /dev/mapper/rhel-root xfs 17G 4.2G 13G 25% / /dev/vda2 xfs 960M 280M 681M 23% /boot /dev/vda1 vfat 599M 7.1M 592M 2% /boot/efi tmpfs tmpfs 1.9G 0 1.9G 0% /dev/shm
Mount pointFile systemPurpose
/XFS (usually on LVM)The main system: /etc, /usr, /var, /home…
/bootXFS, separate partitionKernel and boot files. Kept separate so the boot loader can always read them

Answer: yes. /boot is a different file system, and on UEFI computers /boot/efi (the EFI partition) is yet another one. On old BIOS computers there is no /boot/efi. Your own layout may be different, so always check with df -hT.

Step 3: Symbolic links (a shortcut that stores a path)

📌 Sticky note / Windows shortcut analogy
A symlink is like a sticky note that says "the file you want is at /home/john/practice/letter.txt". The note is not the file. It only tells you where to look. If that file is moved or deleted, the note points at nothing. If a new file appears with the same name, the note works again.

Technically: a symlink is a small file with its own inode, and the content of that file is just the path text of the target.

A symlink follows the name. When the name disappears, the link is "dangling".
$ echo "Dear Sam" > letter.txt # recreate it, since we deleted it earlier $ ln -s letter.txt letter-soft.txt $ ls -l letter-soft.txt lrwxrwxrwx. 1 john john 10 Oct 21 20:20 letter-soft.txt -> letter.txt
PartMeaning
lFirst letter: this is a symbolic link (a normal file shows -)
rwxrwxrwxAlways shown like this. The target's permissions are what really count
1Link count stays 1
10Size = length of the stored path. "letter.txt" has 10 characters
-> letter.txtThe target it points to

Why symlinks are useful: they can point to a folder, and they can cross file systems. Hard links cannot do either.

Dangling link and "revival"

$ rm letter.txt $ ls -l letter-soft.txt # still listed… $ cat letter-soft.txt # …but broken cat: letter-soft.txt: No such file or directory $ echo "A new letter" > letter.txt # make a NEW file with the same name $ cat letter-soft.txt A new letter # the link works again!

A symlink stores only the name, so any file that later gets that name fits. A hard link never behaves this way; it follows the original data.

The relative-target trap

If the target in ln -s is a relative path, it is read from the folder where the link lives, not from where you typed the command.

$ mkdir files links $ echo hi > files/a.txt $ ln -s files/a.txt links/a.soft # ❌ looks for links/files/a.txt (does not exist) $ ln -s ../files/a.txt links/b.soft # ✅ from links/, go up, then into files $ ln -s ~/practice/files/a.txt links/c.soft # ✅ absolute path: always safe
💡 Beginner advice
When making symlinks, use the absolute path for the target. It avoids this whole problem.

Symlink to a directory

$ ln -s /var/log ~/mylogs $ cd ~/mylogs $ pwd /home/john/mylogs # shows the link's name $ cd -P ~/mylogs $ pwd /var/log # -P = follow to the real directory

Do links stay in sync with the original?

In simple English: "in sync" just means "when I change the original, does the other one show the change too?"

📄 Paper idea
Copy (cp) = a photocopy of a paper. If you write on the original later, the photocopy stays the same.
Hard link = the same paper with two labels stuck on it. There is only one paper, so a change shows under both labels.
Symlink = a note saying "the paper is in drawer 3". You always read the real paper, so you always see the latest version.
Shows my change to the original?Why?
Copy❌ NoIt is a separate file
Hard link✅ YesIt is the same file
Symlink✅ YesIt reads the original file every time
$ echo "version 1" > report.txt $ ln report.txt report.hard $ ln -s report.txt report.soft $ cp report.txt report.copy # an ordinary COPY, for comparison $ echo "version 2" >> report.txt # add a line to the original $ cat report.hard version 1 / version 2 ✅ synced $ cat report.soft version 1 / version 2 ✅ synced $ cat report.copy version 1 ❌ a copy is independent
⚠️ When a hard link stops syncing
Some tools (sed -i, many text editors) save by writing a brand-new file and renaming it over the old one. That new file gets a new inode, so the hard link keeps the old content. Check with ls -li. Adding text with >> keeps the same inode. A symlink is not affected.

Simple version: the editor throws the old paper away and writes a new paper. The hard link label is still stuck on the old paper. The symlink note says "look in drawer 3", so it finds the new paper.

Helpful link commands

More about unlink

unlink removes exactly one name (one entry in a folder). Nothing more.

$ unlink report.soft # removes the symlink; report.txt is untouched $ unlink report.hard # removes one name; report.txt link count goes 2 → 1 $ unlink *.txt # ❌ error: unlink takes only ONE name $ unlink school # ❌ error: it does not work on folders
What you unlinkWhat happens
A symlinkThe link is removed. The target file is never touched
A hard linkThat one name is removed, link count goes down by 1. Data is freed only when the last name is gone
A normal file with one nameThe file is deleted (same as rm)
A folderFails. Use rmdir or rm -r
  • unlink vs rm: for one file they do the same job. rm is more powerful (many files, -r, -i, wildcards). unlink is simple: one name, no options, so it is harder to make a big mistake.
  • It does not use a Recycle Bin. There is no undo, just like rm.
⚠️ Symlink to a folder
To remove a symlink that points to a folder, type unlink mylogs or rm mylogs. Do not type rm mylogs/ with a slash at the end. The slash makes the command look at the real folder behind the link.

Real examples on RHEL: /bin → /usr/bin is a symlink; systemctl enable creates symlinks in /etc/systemd/system/; backup tools like rsync --link-dest use hard links to save space.

3.9 Match File Names with Shell Expansions

🟢 In simple words
Before a command runs, the shell (the program that reads your typing) changes some special symbols into real names or values. This section is short and less important. Learn the table, try the examples, and move on.

Glob patterns: the big idea

The command (like ls or rm) never sees your pattern; it only sees the final result. Example: rm a* becomes rm apple apricot.

💡 Safety trick
Put echo in front of any command to preview what the shell will turn your pattern into, without doing anything. echo a* is safe; rm a* is not.

[!abc] or [^abc]One character that is not a, b or c
[[:alpha:]]One letter
[[:lower:]] / [[:upper:]]One lowercase / uppercase letter
[[:digit:]]One digit 0–9
[[:alnum:]]One letter or digit
[[:punct:]]One punctuation mark
[[:space:]]Space, tab or newline
$ mkdir ~/practice/fruit ; cd ~/practice/fruit $ touch apple apricot banana cherry grape kiwi mango melon $ ls a* apple apricot # starts with a $ ls *an* banana mango # contains "an" $ ls *e apple grape # ends with e $ ls [ag]* apple apricot grape # starts with a or g $ ls [!a]* banana cherry grape kiwi mango melon # does NOT start with a $ ls ???? kiwi # exactly 4 characters $ ls ????? apple grape mango melon # exactly 5 characters $ ls ???* (everything) # at least 3 characters
  • No match? The shell leaves the pattern as typed, and the command usually complains.
  • In [[:digit:]], the outer [ ] means "one character from this set" and [:digit:] is the named set. Do not write [digit], which means one of the letters d, i, g, t.
  • Wildcards skip hidden files (starting with a dot) unless you type the dot yourself.
  • Wildcards are not regular expressions. For example ^ does not mean "start of name" here.

Shell expansion types

Brace expansion: creates text

$ echo report_{jan,feb,mar}.txt report_jan.txt report_feb.txt report_mar.txt $ echo photo{1..5}.jpg photo1.jpg photo2.jpg photo3.jpg photo4.jpg photo5.jpg $ echo file{a..c}.txt filea.txt fileb.txt filec.txt $ echo file{a,b}{1,2}.txt filea1.txt filea2.txt fileb1.txt fileb2.txt $ echo file{01..10} # zero-padded: file01 … file10 $ mkdir -p trip/{day1,day2,day3} # three folders in one go $ touch week{1..2}_day{1..5}.log # 10 files: every combination

Tilde expansion

$ echo ~ /home/john $ echo ~alice /home/alice # another user's home $ echo ~nobody1 ~nobody1 # unknown user: stays as plain text

Do not confuse ~tmp (home of a user named "tmp") with /tmp.

Variable expansion

A variable is a labelled box that holds text.

$ city=London # NAME=value (no spaces around =) $ echo $city London $ echo ${city}_trip London_trip # braces mark where the name ends $ echo $city_trip # shell looks for a variable called "city_trip" → empty!

Variable names use letters, digits and underscores, are case-sensitive, and cannot start with a digit.

Command substitution

$( ) runs the command inside and pastes its output into your line.

$ echo Today is $(date +%A). Today is Wednesday. $ myhost=$(hostname -s) ; echo $myhost $ cp notes.txt notes_$(date +%F).txt # notes_2026-10-21.txt (year-month-day) $ cp notes.txt notes_$(date +%s).txt # seconds since 1970: always unique
  • An older style uses backticks (the key left of 1). It still works but looks like a single quote and cannot be nested. Prefer $( ).

Practice Project: Build a Family Recipe Book

This one project uses every skill from the chapter. Type each block and check the result with ls -R after every step.

Step 1: Build the folder tree (mkdir -p, brace expansion)

$ cd ~/practice $ mkdir -p recipes/{breakfast,lunch,dinner} $ touch recipes/breakfast/{pancakes,omelette,toast}.txt $ touch recipes/lunch/{salad,burger}.txt $ touch recipes/dinner/{pasta,pizza}.txt $ ls -R recipes

Step 2: Copy and rename (cp, mv)

$ mkdir favourites $ cp recipes/lunch/salad.txt favourites/ $ cp -r recipes/dinner favourites/ # whole folder, needs -r $ mv recipes/breakfast/omelette.txt recipes/breakfast/cheese_omelette.txt # rename

Step 3: Use wildcards

$ ls recipes/*/*a.txt # every recipe whose name ends in "a" $ cp recipes/lunch/*.txt favourites/ # copy all lunch recipes $ echo recipes/dinner/p* # preview: pasta and pizza

Step 4: Add links

$ echo "bun, beef, cheese, onions" > recipes/lunch/burger.txt $ ln recipes/lunch/burger.txt favourites/burger_hard.txt # hard link $ ln -s ~/practice/recipes/dinner/pizza.txt favourites/pizza_link.txt # symlink $ ls -li recipes/lunch/burger.txt favourites/burger_hard.txt favourites/pizza_link.txt # burger files: same inode, link count 2. pizza_link: different inode, starts with l $ mv recipes/dinner/pizza.txt recipes/dinner/pizza_margherita.txt $ cat favourites/pizza_link.txt # broken: the symlink followed the OLD name $ mv recipes/lunch/burger.txt recipes/lunch/burger_deluxe.txt $ cat favourites/burger_hard.txt # still works: hard link followed the data

Step 5: Dated backup (command substitution)

$ cp favourites/salad.txt favourites/salad_$(date +%F).txt $ ls favourites

Step 6: Clean up safely (rmdir vs rm -r)

$ rm favourites/salad.txt # one file $ rmdir favourites rmdir: failed to remove 'favourites': Directory not empty $ rm -r favourites # removes folder and contents $ cd ~ $ rm -r ~/practice # finished: tidy up everything
  • You cannot delete a folder while you are inside it: cd .. first.
  • cd - only returns to the previous folder if your last move was a single cd.
