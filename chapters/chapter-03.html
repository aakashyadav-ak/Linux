3.1 The Linux File System Tree

Windows has drives like C: and D:. Linux has no drive letters. Everything is in one upside-down tree. The top is the root directory, written /.

/ (root) ├── boot files to start the computer ├── dev hardware as files ├── etc system settings ├── home │ ├── john │ └── alice ├── root home of the administrator ├── run data of running programs ├── tmp temporary files ├── usr installed programs (bin, sbin, local) └── var logs, mail, databases
  • / has two jobs: the top folder, and the separator in a path. /etc/issue = file issue inside etc inside /.
Do not mix up/ is the top of everything. /root is only the home folder of the administrator.
DirectoryWhat it holds
/bootFiles needed to start (boot) the computer
/devDevice files for hardware (disks, keyboard)
/etcSystem settings (configuration files)
/homePersonal folders of normal users
/rootHome folder of the administrator
/runData of running programs. Erased at reboot
/tmpTemporary files. Old ones deleted after about 10 days
/usrInstalled software. /usr/bin user commands, /usr/sbin admin commands, /usr/local software you add
/varData that changes but must survive reboot: logs, mail, databases. /var/tmp is cleaned after about 30 days

In RHEL, /bin, /sbin, /lib, /lib64 are just shortcuts (symbolic links) to the same names inside /usr. So /bin/ls and /usr/bin/ls are the same program. The official map: man 7 hier.

$ ls -ld /bin
lrwxrwxrwx. 1 root root 7 ... /bin -> usr/bin

Wait: if everything is under /, why is /boot a different file system?

Good question. There are two different ideas:

  • The tree is what you see: one single set of folders starting at /.
  • A file system is how a disk partition stores data (XFS, ext4, vfat…). Each partition has its own.

Linux builds the one tree by mounting partitions onto folders (called mount points). The folder /boot looks like any other folder, but behind it sits a separate partition with its own file system.

AnalogyA building (the tree) with one main entrance. Behind the door labelled "boot" is a separate storage room (another partition). You walk in the same way, but the room is a different space.

Typical RHEL on a UEFI computer (see it with df -h or lsblk -f):

$ df -hT
Filesystem             Type   Size  Used Avail Use% Mounted on
/dev/mapper/rhel-root  xfs     17G  4.2G   13G  25% /
/dev/vda2              xfs    960M  280M  681M  23% /boot
/dev/vda1              vfat   599M  7.1M  592M   2% /boot/efi
tmpfs                  tmpfs  1.9G     0  1.9G   0% /dev/shm
Mount pointFile systemPurpose
/XFS (usually on LVM)Main system: /etc, /usr, /var, /home…
/bootXFS (separate partition)Kernel and boot files, kept apart so the bootloader can always read them
/boot/efivfat (FAT), the EFI System PartitionNeeded on UEFI computers. Holds the firmware boot programs. It is mounted inside /boot

So yes, /boot is a different file system, and /boot/efi is another one again (on UEFI systems; on old BIOS systems there is no /boot/efi). Your layout may differ, so always check with df -h.

3.3 Specify Files by Name

Absolute and relative paths

A path is the address of a file.

Absolute path
Full address from the top. Starts with /. Works from anywhere.
/home/john/school
Relative path
Route from where you are now. Does not start with /.
From /home/john: school
You are in /home/john /home ├── alice └── john ← YOU ARE HERE ├── school absolute: /home/john/school relative: school └── photos Alice's folder: absolute: /home/alice relative: ../alice
One-second ruleFirst character is / → absolute. Anything else → relative.
  • Spaces: my file.txt looks like two names to the shell. Use quotes "my file.txt" or write my_file.txt.
  • Capital letters matter: Notes.txt and notes.txt are two different files on Linux (XFS, ext4).

Hidden files

A name that starts with a dot (.bashrc) is hidden. See them with ls -a.

What does "tidy" mean?Tidy means neat and in order, with no mess. Your home folder holds many small settings files like .bashrc. If ls showed them all, your own documents would be lost in clutter. So Linux hides them by default to keep the list clean and easy to read.

Hidden is not secret. Anyone can see hidden files with ls -a. To really protect a file, use permissions (later chapter).

3.5 Manage Files with Command-line Tools

touch: make an empty file

If the file does not exist, it is created. If it exists, only its "last modified" time is updated.

$ touch todo.txt
$ echo "buy milk" > note.txt     # a file WITH text
$ cat note.txt
buy milk

cp: copy

A copy is a second, independent file. Change one, the other stays the same.

$ cp note.txt note_backup.txt
$ cp -r school school_copy        # folders need -r
$ cp school/maths.txt .           # dot = into this folder
$ cp a.txt b.txt c.txt school/    # many files into a folder (last word = folder)
  • Without -r, cp skips folders.
  • It overwrites without asking. Use cp -i to be asked.

mv: move AND rename

The same command does both. Change the folder part = move. Change the last part = rename.

$ mv note.txt shopping.txt        # rename
$ mv shopping.txt school/         # move into school
$ mv -v school/shopping.txt .     # -v shows what happened
$ mv school photos old_stuff      # last word must be an existing folder

mv works on folders without -r. It also overwrites silently (use -i).

rm, mkdir, rmdir

$ rm todo.txt                       # delete a file
$ rm school
rm: cannot remove 'school': Is a directory
$ mkdir music videos                # several folders
$ mkdir -p trip/day1 trip/day2      # -p creates missing parents
$ rmdir music                       # only if EMPTY
$ rm -r trip                        # folder and everything inside
The -p typo trapmkdir video/seen gives an error if video is missing (this protects you). mkdir -p video/seen silently creates a new wrong folder video. Use -p only when you are sure of the spelling.

If you give both -i and -f, -f wins.

Safe-delete habit

$ pwd                 # 1. where am I?
$ ls -l report*       # 2. what does my pattern match?
$ rm report_old.txt   # 3. delete only now
No Recycle Bin on the command linerm deletes immediately. There is no undo. A restore needs an existing copy (backup or VM snapshot) and is reliable. A recovery tool (testdisk, photorec) tries to dig data off the disk and is uncertain. Stop using the disk at once if you need recovery. Take a VM snapshot before risky practice.

3.7 Make Links Between Files

A link lets one file be reached by more than one name, without copying it. There are two kinds: hard links and symbolic links (symlinks). First we need the inode.

Step 1: What is an inode?

Phone contacts analogy Contact name "Mom" = the file name
Contact entry (number, address, birthday) = the inode (information about the file)
The real person who answers = the data

Every file has three separate pieces:

NAME (report.txt) ──► INODE #8924107 ──► DATA ("Quarterly numbers…") stored in a folder owner, permissions, size, the real content times, link count, on disk where the data is
  • The name is stored in the folder, not in the inode. A folder is just a list: "name → inode number".
  • Because the name is separate, one file can have several names. That is how hard links work.
  • Inode numbers are unique only inside one file system.
$ cd ~/practice
$ echo "Dear Sam" > letter.txt
$ ls -i letter.txt
1049233 letter.txt
$ stat letter.txt
  File: letter.txt
  Size: 9     Blocks: 8     regular file
Inode: 1049233   Links: 1
Access: (0644/-rw-r--r--)  Uid: (1000/ john)  Gid: (1000/ john)
Context: unconfined_u:object_r:user_home_t:s0
Access: ... (last read)   Modify: ... (content changed)
Change: ... (inode changed)   Birth: ... (created)

More about df -i and link counts

Every file and folder uses one inode. A file system creates a fixed number of inodes when it is made. You can run out of two different things:

  • Space (blocks): checked with df -h.
  • Inodes: checked with df -i.
$ df -i /
Filesystem   Inodes  IUsed   IFree IUse% Mounted on
/dev/vda3   8910848 245120 8665728    3% /

IUsed = number of files and folders that exist. IFree = how many more you can create. Imagine a disk with 100 GB free but 0 inodes free (for example after creating millions of tiny files, like mail or cache files). You then cannot create any new file, and the error says "No space left on device" even though df -h shows free space. When that happens, check df -i and delete files you do not need.

Link count of a folder: a new empty folder has a count of 2: its own name in the parent, plus its own . entry. Each subfolder adds 1 more, because the subfolder's .. points back to it.

$ mkdir box ; ls -ld box
drwxr-xr-x. 2 john john ... box        (count 2)
$ mkdir box/a box/b ; ls -ld box
drwxr-xr-x. 4 john john ... box        (count 4 = 2 + two subfolders)

Ordinary files inside the folder do not change the folder's count.

Step 2: Hard links (a second name for the same file)

Nickname analogyYour friend is "Sam" to you and "Sammy" to his family. Two names, one person. Stop using one name, the person still exists. Only when every name is gone is nobody left.
letter.txt ──┐ ├──► INODE #1049233 (Links: 2) ──► DATA "Dear Sam" letter-hard.txt ──┘

Syntax: existing file first, new name second. Neither name is "the original"; they are equals.

$ ln letter.txt letter-hard.txt
$ ls -il letter.txt letter-hard.txt
1049233 -rw-r--r--. 2 john john 9 Oct 21 20:10 letter-hard.txt
1049233 -rw-r--r--. 2 john john 9 Oct 21 20:10 letter.txt
$ rm letter.txt
$ cat letter-hard.txt
Dear Sam        # data still safe, link count is now 1

Same inode number = same file. Link count 2 = two names. Data is freed only when the last name is removed.

Two limits of hard links

  1. Regular files only. No folders.
  2. Same file system only (see the /boot explanation in 3.1). An inode number only has meaning inside its own file system. A hard link from /boot to /home fails: 
    ln: failed to create hard link '/home/john/x' => '/boot/y': Invalid cross-device link

Step 3: Symbolic links (a shortcut that stores a path)

Sticky note / Windows shortcutA symlink is a sticky note saying "the file is at /home/john/practice/letter.txt". The note is not the file. If the file is moved or deleted, the note points at nothing.

A symlink is a small file with its own inode. Its content is just the path text of the target.

$ echo "Dear Sam" > letter.txt
$ ln -s letter.txt letter-soft.txt
$ ls -l letter-soft.txt
lrwxrwxrwx. 1 john john 10 Oct 21 20:20 letter-soft.txt -> letter.txt
  • l at the start = symbolic link. -> shows the target.
  • Size 10 = length of the text "letter.txt" (10 characters).
  • Symlinks can point to folders and cross file systems. Hard links cannot.

Dangling link and revival

$ rm letter.txt
$ cat letter-soft.txt
cat: letter-soft.txt: No such file or directory   # dangling (broken)
$ echo "A new letter" > letter.txt
$ cat letter-soft.txt
A new letter                                       # works again!

A symlink remembers only the name, so any new file with that name fits.

Relative-target trapA relative target is read from the folder where the link lives.
$ ln -s files/a.txt links/a.soft            # wrong: looks in links/files/a.txt
$ ln -s ../files/a.txt links/b.soft         # right
$ ln -s ~/practice/files/a.txt links/c.soft # absolute: always safe
Beginner advice: use the absolute path for the target.
$ ln -s /var/log ~/mylogs
$ cd ~/mylogs ; pwd
/home/john/mylogs
$ cd -P ~/mylogs ; pwd      # -P = follow to the real folder
/var/log

Do links stay in sync with the original? (simple English)

"In sync" means: when you change the original, does the other one show the change too?

Photocopy idea Copy (cp) = a photocopy of a paper. If you write on the original later, the photocopy does not change.
Hard link = the same paper with two labels on it. There is only one paper, so any change shows under both labels.
Symlink = a note saying "the paper is in drawer 3". You always read the real paper, so you see the latest version.
$ echo "version 1" > report.txt
$ ln report.txt report.hard
$ ln -s report.txt report.soft
$ cp report.txt report.copy
$ echo "version 2" >> report.txt     # add a line to the original
$ cat report.hard      version 1 / version 2   ✅ changed
$ cat report.soft      version 1 / version 2   ✅ changed
$ cat report.copy      version 1               ❌ not changed
One exception for hard linksSome programs (sed -i, many text editors) do not edit the file in place. They write a new file and rename it over the old one. The new file gets a new inode, so the hard link is left holding the old content. Adding text with >> keeps the same inode and is safe. Check with ls -li.

unlink: remove one name

unlink removes one name (one directory entry). Nothing more.

$ unlink report.soft        # removes the symlink only; report.txt is untouched
$ unlink report.hard        # removes one name; link count of report.txt goes 2 → 1
  • It takes exactly one file name. No options, no wildcards like *, no folders.
  • On a symlink it removes the link, never the target file.
  • On a hard link it removes that name. The data is freed only when the last name is gone.
  • For one file it does the same job as rm. The difference: rm is more flexible (many files, -r, -i), unlink is simple and has no extra options, so it is harder to do damage with.
  • On a folder it fails: use rmdir or rm -r.
Symlink to a folderType unlink mylogs or rm mylogs. Do not type rm mylogs/ with a trailing slash: that refers to the real folder behind the link.

3.9 Shell Expansions (short version)

Before a command runs, the shell rewrites what you typed. The command only sees the final result: rm a* becomes rm apple apricot.

Safety trickPut echo in front to preview. echo a* is safe. rm a* is not.
SymbolMeaningExample

[abc]One of a, b or cls [ag]*
[!abc]One character NOT a, b or cls [!a]*
{a,b} {1..5}Brace: creates namestouch file{1..3}

$ ls a*        apple apricot

$ echo report_{jan,feb}.txt
report_jan.txt report_feb.txt
$ cp notes.txt notes_$(date +%F).txt   # dated backup name

  • Wildcards skip hidden files unless you type the dot.
