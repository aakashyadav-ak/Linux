Section 2.2

Consoles and Terminals

What is a console?

A console is the main way to talk to a computer directly, using the keyboard and screen attached to it. It is also where the system prints boot and kernel messages. Because it does not need the network, it is how admins fix a server that cannot be reached by SSH.

🖥️ Physical console

  • The real keyboard + monitor connected to the machine
  • On a VM, the VM window acts as the physical console
  • Shows boot messages and kernel messages
vs

🪟 Virtual console

  • A text screen created by software (the kernel)
  • Up to 6 can share ONE physical screen: tty1 to tty6
  • Each one has its own independent login
One keyboard and screen can show several separate text logins (virtual consoles). Windows and remote logins use pseudo-terminals (pts).
TypeNotes
Virtual console (TTY)Text login. Switch with Ctrl+Alt+F1 to F6. Names: /dev/tty1 to /dev/tty6.
Terminal emulator (GUI)A window inside the desktop. RHEL 10 uses Ptyxis.
Pseudo-terminal (PTY / PTS)Used by GUI terminal windows, SSH and tmux. Names: /dev/pts/0, /dev/pts/1.
Serial consoleOver a serial port (ttyS0). For servers without a screen, routers, embedded devices.
Physical / system consoleDirect keyboard and monitor.
  • TTY originally meant Teletypewriter, an old machine with a keyboard and printer.
  • GUI mode: unlimited terminal windows. Text mode: 6 text consoles.
  • Headless server: no permanent keyboard or screen. Admins use SSH or a serial console. Many servers run without a GUI to save resources.
🖥️
Which console does the GUI use?

On a system with a desktop, the graphical login screen runs on tty1 and your desktop session usually starts on tty2. (Older guides say tty7, which is outdated.) After you log out of the desktop, you return to the login screen on tty1.

How to switch consoles

  • Press Ctrl+Alt+F3 to jump to text console 3. Log in there. Press Ctrl+Alt+F1 or F2 to return to the desktop.
  • In a VM, click inside the VM window first so the keys reach the guest and not your host PC.
🔎
Section 2.3

Which Console Am I Using?

The tty command prints the name of the terminal you are using.

Terminal$ tty /dev/tty1 # text console number 1 (local screen) /dev/pts/0 # terminal window in GUI, or an SSH session
🔴
You see /dev/tty1 on a RHEL 10 server. What does it mean?

You are logged in on virtual console 1 of the machine itself, meaning the VM window / local screen, not over SSH. On a server without a desktop, tty1 is the first text login screen, so seeing /dev/tty1 is completely normal. If you connected with SSH, you would see /dev/pts/0 instead.

tty showsMeaning
/dev/tty1 … tty6Local text console (virtual console)
/dev/pts/NGUI terminal window or SSH session
/dev/ttyS0Serial console

More ways to check how you are logged in

Terminal$ who # who is logged in and from where student tty1 2026-10-20 09:12 student pts/0 2026-10-20 09:30 (192.168.100.9) $ w # same, plus what each user is running $ echo $0 # the shell name: -bash means a login shell $ loginctl list-sessions # sessions managed by systemd

Section 2.5

Regular User vs Root User

👤 Regular user

  • Prompt: $
  • Power: limited
  • Home: /home/username
  • Created with useradd
vs

🔴 Root user

  • Prompt: #
  • Power: full control
  • Home: /root
  • Exists on every system
  • A regular user can borrow admin power with sudo after joining the wheel group:
Terminal# usermod -aG wheel username
⚠️
Do not forget -a

-aG means append to the group. Using only -G replaces all of the user's other groups.

  • Sudo rules live in /etc/sudoers. Edit them only with visudo, which checks for mistakes.
  • Ticking "Make this user administrator" during install puts the user in wheel.
  • If the root account is locked during install, you cannot log in as root. Use your admin user with sudo.
sudo commandsu -
What it doesRuns one command as rootOpens a full root shell
Password askedYour own passwordRoot's password
LoggingEvery command is recordedOnly the su itself
Best forSingle admin tasks (safer)Longer admin sessions

Section 2.6

What Is a Shell?

A shell is a program that reads what you type and passes the request to the kernel.

👤 You→Command→🐚 Shell→System call→🧠 Kernel→⚙️ Hardware

Interpreter vs compiler

📜 Interpreter

  • Reads and runs line by line, live
  • No separate output file
  • Example: Bash
vs

⚙️ Compiler

  • Converts the whole program to machine code first
  • Creates an executable file
  • Example: gcc (C compiler)

Types of shell

ShellPlatformNote
cmd.exeWindowsOld command interpreter
PowerShellWindowsPowerful scripting
shUNIXOriginal Bourne shell
bashLinux, RHEL defaultBourne Again SHell: improved sh, great for scripting
zshmacOS defaultCan be installed on RHEL
📘
IOS is not Linux

IOS = Internetwork Operating System, Cisco's OS for routers and switches. It is not part of RHEL.

Interactive vs non-interactive

  • Interactive: you type commands and read the output.
  • Non-interactive: runs on its own, like a script or a cron job.

Login shell vs non-login shell

A login shell is a shell started as part of logging in (a fresh start as that user). A non-login shell is a shell started from inside a session, which reuses what you already have.

Which start-up files Bash reads depends on how the shell was started.
su root (non-login)su - root (login)
Same assusu - (also su -l, su --login)
Shell typeNon-loginLogin
EnvironmentKeeps your old one (PATH, variables)Builds a fresh one for root
Start-up files readOnly ~/.bashrc/etc/profile → ~/.bash_profile → ~/.bashrc
Working directoryStays where you wereGoes to root's home /root
echo $0 showsbash-bash
Password askedRoot'sRoot's
Try it$ pwd /home/student $ su root # non-login Password: # pwd /home/student # did not move # exit $ su - root # login Password: # pwd /root # moved to root's home # echo $0 -bash # the leading dash = login shell
💡
Rule of thumb

Almost always use su - (with the dash). It gives you a clean, correct environment and avoids odd behaviour. Plain su is a common beginner mistake.

📘
Why does this matter?

Settings in /etc/profile and ~/.bash_profile (like PATH changes) are only applied in login shells. A non-login shell may be missing them, so commands can behave differently. When root runs su user, no password is needed.

Check and change your shell

Terminal$ echo $SHELL # your login shell $ cat /etc/shells # shells you are allowed to use $ chsh -s /bin/zsh # change your login shell $ shopt -q login_shell && echo login || echo non-login

A shell change takes effect after you log out and log in again. No reboot is needed.

Where commands live

  • Normal commands: /usr/bin. Admin commands: /usr/sbin. On modern RHEL, /bin and /sbin are links to them.
  • The shell finds them using the PATH variable: echo $PATH.
  • Find a command: which ls or whereis passwd.

Section 2.9

GUI vs CLI Mode (systemd Targets)

Linux decides what to start at boot using targets. Two matter most:

🖥️ GUI mode

  • Target: graphical.target
  • Full desktop
  • Uses more resources
vs

⬛ CLI mode

  • Target: multi-user.target
  • Text only, no desktop
  • Lighter and faster
Terminal# systemctl get-default graphical.target # Switch NOW (temporary, gone after reboot) # systemctl isolate multi-user.target # to CLI # systemctl isolate graphical.target # to GUI # Make it permanent (survives reboot) # systemctl set-default multi-user.target # boot to CLI # systemctl set-default graphical.target # boot to GUI # Bigger font on the text console # setfont sun12x22
isolateset-default

Save your work first

Section 2.10

Logging In to a Remote System with SSH

  • SSH = Secure Shell. It gives you a shell on another machine over an encrypted connection.
  • Client program: ssh. Server service: sshd. Default port: 22.
Key-based login: the secret half never leaves your PC.

3 checks before connecting

#CheckHow
1Connectivity: can you reach the server?ip a to find its IP, then ping
2Service: is sshd running?systemctl status sshd
3Credentials: a password or a keyAsk the admin, or create keys
SSH commands$ ssh remoteuser@remotehost # password login $ ssh -i mylab.pem remoteuser@remotehost # key login $ exit # log out (or Ctrl+D)

Key-based login

  • Private key = secret, stays with you (like a password).
  • Public key = placed in the user's account on the server. It does not need to be secret.
  • Copy a .pem file to your machine with the GUI, scp, or WinSCP (a Windows tool that copies files over SSH).
  • The private key file must not be readable by others:
Terminal$ chmod 600 mylab.pem # 400 also works

If the permissions are wrong, OpenSSH refuses to use the key.

The first-login warning

First connectionThe authenticity of host 'remotehost (192.0.2.42)' can't be established. ED25519 key fingerprint is SHA256:AbCdEf123... Are you sure you want to continue connecting (yes/no)?
  • yes saves the server's host key so you are not asked again.
  • no closes the connection.
  • If a saved host key later changes, SSH blocks you. It can mean someone is pretending to be that server (a man-in-the-middle attack).
  • Saved host keys live in ~/.ssh/known_hosts.
⚠️
Root over SSH

The default is PermitRootLogin prohibit-password: root cannot use a password over SSH (key login can still be set up). Normal practice: log in as a regular user, then use sudo or su -.

Useful commands

Terminal$ ip a # IP addresses ("inet" = IPv4, "inet6" = IPv6) $ nmcli con show # list network connections $ nmcli con down ens160 # bring a connection down $ nmcli con up ens160 # bring it up $ who -a # logged-in users, detailed $ w # logged-in users and what they run $ last # login history $ su - root # become root with a login shell
⚠️
Never run nmcli con down over SSH

You will cut off your own connection. Do it from the VM console.

What is the Super key?

Super = the Windows key (⊞) on a PC keyboard. On a Mac keyboard it is the Command (⌘) key. It is the key between Ctrl and Alt. Super+L means: hold the Windows key and press L.

If your host Windows grabs the key (for example Windows+L locks your host PC), click inside the VM window or use full-screen mode so the key is sent to the VM. You can always click Activities in the top-left instead.

Start a terminal

  • Press the Super (Windows) key, type terminal, press Enter.
  • Or press Alt+F2, type ptyxis, press Enter.

Workspaces

  • Separate desktops to group windows by task.
  • Dynamic (default): empty ones are removed. Fixed: a set number always shows.
  • Change under System menu → Settings → Multitasking.

Lock, log out, power

  • Lock: the system menu lock icon, or Super+L. Unlock with Enter or Space, then your password.
  • Log out: system menu → Power icon → Log Out.
  • Power off / restart: the Power icon, or Ctrl+Alt+Del.
  • On shutdown you may see "Install pending software updates". You can untick it.

Executing Commands with Bash

Running more than one command

SymbolMeaningExample
;Run one after another, alwayscd /tmp; ls; pwd
&&Run the next only if the previous succeededcd /etc && cat passwd
||Run the next only if the previous failedcd /nodir || echo "Not found"
| (pipe)Send the output of one command into the nextcat /etc/passwd | grep root
command 1→&& success? →→command 2
command 1→|| failed? →→command 2
📘
Success and failure

Every command leaves an exit status. 0 means success; anything else means failure. See it with echo $? right after a command. && and || read this number.

Pipe examples$ ls | head -5 # first 5 items $ history | grep ssh # find ssh commands $ cat /etc/passwd | wc -l # count lines

Simple commands

Terminal$ whoami $ mkdir l1; cd l1; touch testing # three commands on one line $ date # date and time $ date +%R # 24-hour time, e.g. 17:58 $ date +%r # 12-hour with AM/PM $ date +%x # date, e.g. 04/29/25 $ passwd # change your password
  • A normal user changes only their own password and must enter the old one first.
  • Root can run passwd username to set anyone's password.
  • Use strong passwords (mixed characters, not a dictionary word).
  • Linux does not need file extensions. Use file to see the real type.

Viewing files

Tab completion

  • Tab once completes a unique name. Tab twice lists all matches.
  • Works on commands, file names and options. Try useradd -- then Tab Tab.

A long command over several lines

End the line with \. The shell shows a > continuation prompt. Do not type the > yourself, because it would act as redirection.

Terminalhead -n 3 \ /usr/share/dict/words \ /usr/share/dict/linux.words

⚠️
History is a security risk

~/.bash_history can contain passwords typed in commands. history -c clears only the current session's memory; the saved file is updated when the shell exits.
