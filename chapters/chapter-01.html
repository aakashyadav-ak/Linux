1.1

What is Linux?

Linux is a free, open-source operating system kernel. The kernel is the core program that sits between your hardware (CPU, memory, disk) and the programs you run. It was started by Linus Torvalds in 1991.

💡
Easy picture: engine vs car

The kernel is like a car's engine: essential, but you cannot drive an engine on its own. A distribution (such as RHEL, Ubuntu or Fedora) is the whole car: engine + steering wheel + seats + dashboard, ready to drive.

  • Licence: GPL v2, which allows anyone to use, study, change and share the code.
  • The GNU project (1983, Richard Stallman) supplies many core tools (shell, compilers, utilities), so you will sometimes see the name GNU/Linux.
  • Strictly speaking, "Linux" is the kernel. A complete system made of kernel + tools = a distribution (distro).

What does "open source" mean?

Think of a recipe. With open source, the recipe (source code) is public: anyone can read it, improve it and share their version. With closed-source software you only get the finished dish.

UNIX and Linux

UNIX began in 1969 at Bell Labs. It is a powerful multi-user, multitasking operating system, and it set the design that Linux copies.

🧬
Linux is Unix-like, not Unix

Linux was written from scratch. It copies Unix's ideas and behaviour but contains no Unix code. That is why it is called Unix-like.

UNIX is both a family and a trademark. Many Unix systems are proprietary (IBM AIX, Oracle Solaris, HP-UX). Others are free (FreeBSD), and macOS is a certified UNIX. Linux itself is not a UNIX product.

🏗️
1.3

How Linux Is Built

A Linux system is built in layers. Each layer only talks to the one directly below it.

You type a command → the shell passes it on → the kernel talks to the hardware → the answer travels back up.

A restaurant analogy

🙋 You (customer)→🧑‍🍳 Shell (waiter)→👨‍🍳 Kernel (kitchen chef)→🥕 Hardware (ingredients)

You place an order (type a command). The shell carries it to the kernel. The kernel uses the hardware to prepare the result, and the answer comes back to your screen.

The kernel: heart of the system

The kernel talks directly to the hardware. Its jobs:

⚙️
ProcessesDecides which program runs, and when.
🧠
MemoryHands out RAM and virtual memory.
🔌
DriversLets the OS use disks, keyboards, network cards.
📞
System callsThe doorway programs use to ask the kernel for help.
🔒
SecurityEnforces file permissions.
🌐
Networking & filesNetwork stack and file systems.
Terminal$ uname -r # kernel version $ uname -a # all system information

The shell: you talk to the kernel through it

The shell is a command interpreter. You type ls; the shell asks the system to list files and prints the answer. It also gives you history, tab completion and scripting (automation). Bash (Bourne Again Shell) is the default on RHEL.

ShellPathNotes
Bash/bin/bashRHEL default. Most scripts use it.
sh/bin/shClassic POSIX shell. On RHEL it simply points to bash.
Zsh/bin/zshFeature-rich, macOS default. Not installed by default on RHEL.
Dash/bin/dashUsed for sh on Debian/Ubuntu, not on RHEL.
Terminal$ cat /etc/shells # shells allowed as login shells $ echo $SHELL # my login shell $ echo $0 # the shell running right now $ ls -l /bin/sh # what does sh point to?

Reading the output of cat /etc/shells

On a minimal server install you will see exactly this:

Output/bin/sh /bin/bash /usr/bin/sh /usr/bin/bash
  • /etc/shells is the list of programs that are allowed to be a user's login shell. Commands like chsh only accept shells from this list.
  • Only two shells exist: sh and bash. A minimal install does not include zsh, dash or csh. If you install one (for example sudo dnf install zsh), it is added to the list.
  • Each shell appears twice (/bin/... and /usr/bin/...) because on modern RHEL /bin is just a shortcut (symbolic link) to /usr/bin. Both paths lead to the same file. ls -ld /bin shows /bin -> usr/bin.
  • sh is a link to bash, so in practice bash is the only real shell on that machine.

File system and userspace

  • File system: how Linux stores and organises data on SSD/HDD/USB: files and folders, permissions (read, write, execute), and where devices are mounted. RHEL default type: XFS.
  • Userspace: everything that runs outside the kernel: tools, libraries and your programs. Kernel space is privileged; userspace is limited. They talk through system calls.
🔧
Common mix-up: shell ≠ terminal

The terminal is the window. The shell (bash) is the program running inside it that reads your commands.

1.5

What is RHEL?

  • Red Hat Enterprise Linux (RHEL) is a commercial Linux distribution from Red Hat, designed for servers, data centres and the cloud.
  • It offers stability, security and up to 10 years of support, plus paid support and regular updates.
  • Source line: Fedora → CentOS Stream → RHEL.
  • Free ways to learn it: the Red Hat Developer Subscription, or compatible rebuilds such as Rocky Linux and AlmaLinux.

2.1

The Boot Process

🔌 Power on→Firmware (BIOS/UEFI)→GRUB→Kernel→systemd→🖥️ Login
StepWhat it does (simple words)
Firmware (BIOS/UEFI)The very first program. It checks the hardware (POST, the power-on self-test) and finds a disk to boot from.
GRUBThe bootloader. Shows the boot menu and loads the kernel. Full form: GRand Unified Bootloader (RHEL uses GRUB 2).
KernelThe core of Linux. Starts talking to the hardware.
initramfsA tiny temporary file system that helps the kernel find your real disk.
systemdStarts all services and brings up the login screen.

BIOS vs UEFI vs EFI

  • Legacy BIOS: the old firmware. Boots from the MBR (first sector of the disk).
  • UEFI: the modern firmware. Boots from a special EFI partition and uses GPT disks.
  • EFI is the older name of UEFI. People often use the two names for the same thing.
  • In VMware: VM Settings → Options → Advanced → Firmware type.
💡
Recommendation

Choose UEFI for new installs. It is the modern standard.

The firmware chip (ROM / EEPROM)

A small chip on the motherboard stores the BIOS/UEFI program and keeps it even with the power off. When you power on, the CPU runs that program first, which runs POST, then hands control to GRUB. Updating the BIOS is called flashing because you rewrite this chip.

TypeFull nameCan it be changed?
ROMRead-Only MemoryNo, fixed at the factory
PROMProgrammable ROMWritten once
EPROMErasable PROMErased with UV light, then rewritten
EEPROMElectrically Erasable PROMErased and rewritten with electricity
FlashA modern EEPROMUsed on today's motherboards
📘
Not the same as CMOS

ROM/EEPROM stores the firmware program. CMOS is tiny memory that stores settings (clock, boot order), kept alive by the coin battery on the motherboard.

🖥️
In VMware

The VM has a virtual firmware chip, so there is no physical ROM. Its settings live in the VM's .nvram file. If the VM's boot settings get messed up, deleting that file resets them.

3.2

Network Types in VMware

Every network has addresses (IP addresses). Before comparing modes, two ideas help:

  • Private IP: used inside a home or office network, such as 192.168.x.x, 10.x.x.x or 172.16–31.x.x. It cannot be reached directly from the internet.
  • Public IP: the one address your internet provider (ISP) gives your router. Everything in your home shares it.
📘
Who hands out addresses?

A DHCP server gives out private IPs automatically. Your Wi-Fi router is the DHCP server for your real devices. VMware also runs its own virtual DHCP servers for its virtual networks. The three modes simply choose which one the VM talks to.

NAT: the VM shares your PC's connection

NAT: the VM shares your PC's connection
  • What IP do I get? A private IP such as 192.168.N.128 (VMware chooses the subnet; it differs per install).
  • Who gives it? VMware's own virtual DHCP/NAT service (VMnet8), not your Wi-Fi router and not your ISP. Your router only knows about your PC and gives it something like 192.168.1.23.
  • Internet? Yes. VMware translates ("NATs") the VM's traffic so it leaves using your PC's address. Websites see only your router's public IP.
  • Can other devices reach the VM? No, not by default. Your PC can.

Bridged: the VM becomes its own device on the real network

Bridged: the VM is a full citizen of your real network
  • What IP do I get? A private IP from the same network as your PC, for example 192.168.1.45.
  • Who gives it? Your real router (the Wi-Fi vendor's/home router's DHCP). The router treats the VM like a separate laptop.
  • Internet? Yes, same as any device on the network.
  • Reachable by others? Yes: phones and other PCs on your Wi-Fi can connect to it.
  • Caveat: bridging over Wi-Fi sometimes misbehaves, and some college/office networks refuse extra devices. If it fails, use NAT.

Host-only: a private, closed network

Host-only: a private, closed network
  • What IP do I get? A private IP such as 192.168.M.128 from VMware's host-only DHCP (VMnet1).
  • Internet? No. There is no route to your router.
  • Who can talk? Only your PC and other VMs on the same host-only network. Perfect for a safe, isolated practice lab.

Does any mode give the VM a public IP?

No. In all three modes the VM has a private address. The internet only ever sees your router's public IP. Check it: ip a shows the VM's private IP; curl ifconfig.me shows the public one (same as your PC's).

💡
Which should I pick?

Start with NAT. For a multi-VM lab, give each VM two cards: NAT for internet + Host-only for the private lab network (see Part 4).

The Installer Boot Menu (GRUB)

When the ISO boots you see a menu. This menu is GRUB, the bootloader.

OptionWhat it does
Install Red Hat Enterprise Linux 10Starts the installation.
Test this media & installChecks the ISO for corruption (checksum), then installs. Handy on real hardware; skip it for a trusted ISO.
TroubleshootingOpens repair options (below).

Troubleshooting options

  • Install in basic graphics mode: use if the screen is black or broken.
  • Rescue a Red Hat Enterprise Linux system: boots a repair environment. Your installed system is mounted at /mnt/sysimage.
  • Boot from local drive: skips the installer and boots the installed OS.
  • Memory test: tests RAM (not shown on every system).
Rescue Mode# chroot /mnt/sysimage

chroot means "pretend this folder is the root of the system", so you can fix things as if you had booted normally.

GRUB keys

KeyAction
eEdit the selected entry (temporary, lost after reboot)
cOpen the GRUB command line
Ctrl+xBoot with your edits
  • Main settings file on an installed system: /etc/default/grub.
  • Generated config: /boot/grub2/grub.cfg.
  • Apply changes after editing:
Terminal# grub2-mkconfig -o /boot/grub2/grub.cfg

Useful skill

A lost root password can be reset by adding rd.break to the kernel line at the GRUB menu.

What is a partition?

Splitting one physical disk into separate sections: like one big cupboard divided into shelves, each with its own purpose.

Partition table types

TypeUsed withLimits
MBRLegacy BIOS2 TB max, 4 primary partitions
GPTUEFIHuge disks, 128 partitions

Device types

  • Standard partition: fixed size. Simple but hard to resize.
  • LVM: flexible; grow volumes later without reinstalling.
  • LVM thin provisioning: space is used only when needed.
  • Software RAID: combines several disks for speed or safety.
LVM: join disks into a pool, then cut flexible slices from it. Need more room in /home later? Just grow the slice.
💡
LVM in one sentence

Disks are water tanks (PV) poured into one pool (VG), from which you take portions (LV) of any size, and you can resize them later.

Why separate /home and /var?

If logs grow too large they can fill the disk and crash the system. A separate partition limits the damage and keeps user data safe.

3.6

KDUMP

  • What: when the kernel crashes (a "kernel panic"), a second small kernel starts and saves a memory snapshot called a vmcore. Experts use it to find the cause.
  • Cost: it reserves some RAM all the time.
  • Dump location: /var/crash. Config file: /etc/kdump.conf.
Terminal# systemctl enable --now kdump # kdumpctl status
📘
Lab tip

In a small lab VM you can disable KDUMP during install to save RAM.

Network, Root and User

  • Network & Host Name: turn the network ON and set a hostname such as server1.example.com.
  • Root password: the admin (superuser) account.
  • User creation: create a normal user and tick Make this user administrator so it can use sudo.
⚠️
Root over SSH

On RHEL 10 (and 9), root SSH login with a password is disabled by default. Log in as your normal user and use sudo.

4.1

My Lab Environment

Instead of one lonely VM, I run a tiny data centre inside my PC: one desktop-style machine to work from, and two servers to manage over the network, just like a real admin.

Two virtual network cards per VM: one private LAN for the lab, one NAT card for internet.
MachineRoleInstall typeLab IP
workstationMain machine I log in to and work fromRHEL 10, Server with GUI192.168.100.9
serveraManaged server ARHEL 10, Server (no GUI)192.168.100.10
serverbManaged server BRHEL 10, Server (no GUI)192.168.100.11
  • Domain: lab.example.com (for example servera.lab.example.com).
  • Two network cards per VM: a NAT card for internet, and a Host-only card for the private lab network 192.168.100.0/24.
  • Workflow: I only sit at workstation and use ssh to reach the servers.

Step 1: create the student user and set the hostname (on each VM)

Setup commands# useradd -G wheel student # passwd student # hostnamectl set-hostname servera.lab.example.com

Being in the wheel group gives student administrator rights through sudo.

Step 2: give the host-only card a fixed IP

Setup commands# nmcli device status # find the card name, e.g. ens224 # nmcli connection add type ethernet ifname ens224 con-name labnet ipv4.method manual ipv4.addresses 192.168.100.10/24 # nmcli connection up labnet

Step 3: let the machines find each other by name

Setup commands# tee -a /etc/hosts <<EOF 192.168.100.9 workstation.lab.example.com workstation 192.168.100.10 servera.lab.example.com servera 192.168.100.11 serverb.lab.example.com serverb EOF

Step 4: log in without typing passwords (SSH keys)

On workstation$ ssh-keygen -t ed25519 $ ssh-copy-id student@servera $ ssh student@servera hostname # prints servera.lab.example.com
⚠️
If you clone a VM

A clone is an exact copy, so give it its own hostname and IP, and a fresh machine ID: # rm -f /etc/machine-id && systemd-machine-id-setup.

Snapshot nameTake it when…
clean-installRight after the install and first update
