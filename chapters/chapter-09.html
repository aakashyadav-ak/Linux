9.1 Describe User and Group Concepts

What is a user account?

A user account decides who you are on the system. Every program that runs belongs to some user, and every file has an owner. This is how Linux knows who is allowed to do what.

🏨 Hotel key-card analogy
At a hotel, your room number is what the door lock really checks. Your name on the booking is only a friendly label. Linux works the same way:
• UID (User ID number) = the room number. This is what the system really uses.
• Username (john) = the name label. It is easy for humans to read.
• GID (Group ID number) = the number of a group, like "all guests on floor 3".

The three types of users

Where each kind of user lives on the UID number line.

1) Superuser (root): UID = 0, GID = 0

  • The administrator of the computer. It can read, change or delete any file, install software, create users, and stop any program. Permissions do not stop root.
  • Home folder: /root. Equivalent to "Administrator" on Windows.
  • The system knows root by the number 0, not by the name. Any account with UID 0 is a superuser, so never create a second one.
$ id root uid=0(root) gid=0(root) groups=0(root) $ grep ^root /etc/passwd root:x:0:0:root:/root:/bin/bash
⚠️ Best practice
Do not log in as root for daily work. Log in as a normal user and become root only for the moment you need it (with sudo). One typing mistake as root can destroy the whole system.

2) Regular (standard) user: UID/GID from 1000 upward

  • For people. Limited access: they can work in their own home folder (/home/john) and read most of the system, but they cannot install software, change system settings, or touch other users' files.
  • Default range: 1000 to 60000. (This is set by UID_MIN and UID_MAX in /etc/login.defs. The top is 60000, five digits.) It is not a hard wall: an administrator can raise UID_MAX and the range grows. The special number 65534 is used by the account nobody.
  • When you create a new user, the system gives the next free number starting from 1000.
$ sudo useradd john $ id john uid=1000(john) gid=1000(john) groups=1000(john)

3) Service / system account: UID/GID from 1 to 999

  • For programs (called daemons or services), not for people. Examples: the SSH server, the web server, the time service. Each service gets its own account so that if the service is hacked, the attacker is stuck with that service's small powers, not root's.
  • Normally they have no password and the shell /sbin/nologin, so nobody can log in as them.
  • This range is split in two:
RangeHow numbers are givenMeaning
1 – 200Statically (fixed)Reserved for core services. The same service has the same number on every RHEL computer. Example: sshd is always 74.
201 – 999Dynamically (automatic)Given at install time to services that do not own files. The number can differ from one computer to another.
$ grep -E '^(sshd|chrony):' /etc/passwd sshd:x:74:74:Privilege-separated SSH:/usr/share/empty.sshd:/usr/sbin/nologin chrony:x:992:988:chrony system user:/var/lib/chrony:/sbin/nologin

Reading this: sshd has fixed number 74 (static range). chrony got 992 automatically (dynamic range; yours may differ). Both end with nologin, so no one can open a shell with them.

📝 UID and GID do not have to match
On RHEL, a new user normally gets the same number for UID and GID (john = 1000/1000), but that is only a habit. A user can have UID 1000 and a group with GID 5000. Groups use the same ranges as users.

Important files: where accounts are stored

Linux has no special "user database program". Accounts live in four plain text files in /etc.

Public information on top, secrets at the bottom. The red boxes can only be read by root.
FileWhat it storesWho can read it
/etc/passwdUser account information (name, UID, GID, home, shell)Everyone
/etc/groupGroup information (name, GID, members)Everyone
/etc/shadowPassword hashes and password aging settingsRoot only
/etc/gshadowGroup passwords and group administratorsRoot only

Why two files for users? A long time ago the password hash was in /etc/passwd, and that file must be readable by everyone (programs need to turn UID numbers into names). So everyone could copy the hashes. The fix: keep public data in passwd and move the secret to shadow, which only root can read. The x in passwd is a note saying "the password is in shadow".

How to read one line of /etc/passwd

One line = one user. Seven fields separated by a colon :

john:x:1000:1000:John Smith:/home/john:/bin/bash
1 · UsernamejohnThe login name
2 · PasswordxPlaceholder. Real hash is in /etc/shadow
3 · UID1000User ID number
4 · GID1000Number of the primary group
5 · CommentJohn SmithReal name or note (can be empty)
6 · Home/home/johnFolder you start in after login
7 · Shell/bin/bashProgram that gives you the prompt. nologin = no login
💡 Memory trick
Name : Password : UID : GID : Comment : Home : Shell  → "New People Use Great Computers Here Soon"
$ grep john /etc/passwd # show only john's line john:x:1000:1000:John Smith:/home/john:/bin/bash $ cut -d: -f1,3 /etc/passwd | tail -3 # -d: = split at colons, -f1,3 = keep fields 1 and 3 chrony:992 john:1000 alice:1001

The second command shows username:UID pairs. cut -d: -f1,3 means "cut each line at colons and keep field 1 and field 3".

getent: ask the system "who is this?"

getent means get entries. It reads account information from every source the computer is set up to use, not only the local file.

$ getent passwd john john:x:1000:1000:John Smith:/home/john:/bin/bash $ getent group devs devs:x:10000:john,alice $ getent passwd 1000 # you can also search by UID john:x:1000:1000:John Smith:/home/john:/bin/bash $ grep john /etc/passwd # same answer for a LOCAL user

Groups: primary and secondary

A group is a set of users who share access to some files. Example: the group devs can all read the project folder.

Primary groupSecondary groups
How many per user?Exactly oneZero or many

RHEL uses User Private Groups: when you create john, a group also called john is created, and it becomes his primary group. Only john is in it. For checking permissions, primary and secondary groups count the same: if any of your groups has access, you get access.

How to read the id command

uid=1000(john) gid=1000(john) groups=1000(john),10(wheel),10000(devs)
uid1000(john)User number and name
gid1000(john)Primary group
groups1000, 10, 10000All groups: the primary one first, then the secondary ones (wheel, devs)

Other ways to look: groups john (just the group names), whoami (just my name), who and w (who is logged in now), last (login history).

🔢 How many groups can one user join?
The usual rule taught is: a user can be in up to 16 groups in total, counting the primary group (so 1 primary + 15 secondary). Keep to 16 to be safe, because some network file systems (NFS) only understand 16 groups. Newer Linux kernels can technically handle many more, but 16 is the number to remember.

/etc/login.defs: the default settings for new accounts

When you run useradd, it reads its default rules from /etc/login.defs.

$ grep -E '^(UMASK|PASS_|UID_|GID_|SYS_UID)' /etc/login.defs UMASK 022 PASS_MAX_DAYS 99999 PASS_MIN_DAYS 0 PASS_WARN_AGE 7 UID_MIN 1000 UID_MAX 60000 GID_MIN 1000 GID_MAX 60000 SYS_UID_MIN 201 SYS_UID_MAX 999
SettingMeaning
UMASK 022Default permission "filter" for new files. With 022, new files get rw-r--r-- (644) and new folders rwxr-xr-x (755). Permissions are a later chapter.
PASS_MAX_DAYSMaximum days a password may be used. 99999 days (about 273 years) = never expires
PASS_MIN_DAYSMinimum days before a password may be changed again. 0 = change any time
PASS_WARN_AGEDays of warning before a password expires
UID_MIN / UID_MAXRange of numbers for regular users (1000 to 60000)
SYS_UID_MIN / SYS_UID_MAXRange for system accounts created with useradd -r (201 to 999)
❗ Only new users are affected
If you edit /etc/login.defs, existing users keep their old settings. To change an existing user, use chage (see 9.9). Two more helpers: useradd -D shows the other defaults (from /etc/default/useradd, such as the shell and home base), and /etc/skel holds the starter files (.bashrc …) copied into every new home folder.

9.3 Gain Superuser Access

You work as a normal user. When you need administrator power for one task, you escalate (raise) your privileges. There are two tools: su (switch user) and sudo (super user do).

su and su - (switch user)

su turns your whole shell into another user. You must type that user's password. With no name, it means root.

$ whoami john $ su - alice # become alice (asks for ALICE's password) Password: $ whoami ; pwd alice /home/alice $ exit # go back to john

su versus su - (a dash makes a big difference)

su (no dash)

You become the new user, but you keep your old environment: same folder, same PATH settings. It is a "half switch".
$ su $ pwd /home/john # still john's folder

su - (with dash)

You become the new user completely, as if they had just logged in: their folder, their settings. This is the correct way.
$ su - $ pwd /root # root's own home
💡 Rule of thumb
Always use su - with the dash. Leave with exit. If you are already root, su - alice needs no password.

sudo (super user do)

sudo runs one command with another user's power (root by default). It asks for your own password, not root's, and it writes a log entry for every command. This is why it is safer than sharing the root password.

$ whoami john $ sudo whoami # this one command runs AS ROOT [sudo] password for john: # type JOHN's password (nothing shows on screen) root $ sudo touch /tmp/test.txt $ ls -l /tmp/test.txt -rw-r--r--. 1 root root 0 Oct 24 10:05 /tmp/test.txt

Look at the file's owner: root root, not john. That proves it: everything done with sudo is done by the user root. After the command finishes, you are john again. The password is remembered for about 5 minutes.

CommandWhat it does
sudo commandRun one command as root
sudo -u alice commandRun one command as alice
sudo -iOpen a root login shell (like su - but with your own password). Leave with exit
sudo -sOpen a root shell, keeping more of your own environment

Giving and limiting sudo access

Not every user may use sudo. Two ways to allow a regular user:

Way 1: add the user to the wheel group (easiest)

On RHEL, the group wheel is the "administrators" group. The main sudo file already contains a rule that allows it.

$ sudo usermod -aG wheel john # -aG = Append to Group (keeps john's other groups) $ id john uid=1000(john) gid=1000(john) groups=1000(john),10(wheel) $ sudo grep wheel /etc/sudoers %wheel ALL=(ALL) ALL # %wheel ALL=(ALL) NOPASSWD: ALL

Reading the output: wheel is group number 10 and john is now in it. The first line (no #) is the active rule: everyone in wheel can run everything. The second line starts with #, so it is a comment (switched off). John must log out and log in again for the new group to work.

Way 2: write a rule in the sudoers files

The main file is /etc/sudoers. Better practice: leave it alone and put your own rules in small files inside /etc/sudoers.d/. Always edit with visudo, never with a normal editor. visudo checks the syntax before saving, because a typo can lock everyone out of sudo.

Steps to give john full sudo access:

  1. Open a safe editor on a new file: sudo visudo -f /etc/sudoers.d/john
  2. Press i (insert) and type the rule: john ALL=(ALL) ALL
  3. Press Esc, then type :wq and Enter to save and quit. (If you made a mistake, visudo says syntax error and asks "What now?". Press e to edit again.)
  4. Test it: sudo -l -U john lists john's rights, or log in as john and run sudo whoami.
$ sudo visudo -c # check all sudoers files for mistakes /etc/sudoers: parsed OK /etc/sudoers.d/john: parsed OK

What are the "three ALL"?

john ALL=(ALL) ALL
1 · WHOjohnThe user this rule is for. A % in front (%wheel) means a group
2 · WHERE (1st ALL)ALLOn which computers the rule works. ALL = any
3 · AS WHOM (2nd ALL)(ALL)Which user john may become. ALL = any, including root. (ALL:ALL) adds "any group"
4 · WHAT (3rd ALL)ALLWhich commands john may run. ALL = every command

So john ALL=(ALL) ALL means: "john, on any computer, may become any user and run any command."

Same thing without a password (NOPASSWD)

  1. sudo visudo -f /etc/sudoers.d/john
  2. Change the rule to: john ALL=(ALL) NOPASSWD: ALL
  3. Save and quit (Esc, :wq).
  4. Test: sudo whoami now prints root without asking for a password.
⚠️ Be careful with NOPASSWD
Anyone who sits at john's open terminal gets root power with no barrier. Use it only for automation accounts that log in with SSH keys, never for a normal person.

Allow a whole group (for example, wheel or a new group)

The group wheel is already allowed (see above). To allow another group, such as devs:

  1. Create the group and add people: sudo groupadd devs then sudo usermod -aG devs john
  2. Open a new sudoers file: sudo visudo -f /etc/sudoers.d/devs
  3. Type: %devs ALL=(ALL) ALL (the % means group)
  4. Save and quit. Everyone in devs can now run all commands with sudo.

Block a user from running certain commands

Put the rule in its own custom file. First find the exact path of each command with which (sudoers needs the full path):

$ which useradd adduser userdel /usr/sbin/useradd /usr/sbin/adduser /usr/sbin/userdel $ sudo visudo -f /etc/sudoers.d/custom

Type this one line (an exclamation mark means "not allowed"):

user2 ALL=(ALL) ALL, !/usr/sbin/useradd, !/usr/sbin/adduser, !/usr/sbin/userdel

Read it as: "user2 may run everything (ALL), except useradd, adduser and userdel." Save with :wq. Test as user2:

$ sudo useradd test1 Sorry, user user2 is not allowed to execute '/usr/sbin/useradd test1' as root on server1. $ sudo id # other commands still work uid=0(root) gid=0(root) groups=0(root)
⚠️ Two important notes
• The rule needs ALL, before the "!" items. A line with only !/usr/sbin/useradd gives user2 nothing at all, because there is nothing allowed to subtract from.
• A block list is weak. A user with ALL can run sudo -i to get a root shell and then run any command. So it only prevents mistakes. For real control, use the opposite: allow only a short list, for example user2 ALL=(ALL) /usr/bin/systemctl restart httpd.

How to check failed sudo attempts

If a user without sudo rights tries it, they see this on screen:

$ sudo id alice is not in the sudoers file. This incident will be reported.

"Reported" means it is written to the log file /var/log/secure. The administrator can look there:

$ sudo grep "NOT in sudoers" /var/log/secure Oct 24 10:20:11 server1 sudo[2411]: alice : user NOT in sudoers ; TTY=pts/0 ; PWD=/home/alice ; USER=root ; COMMAND=/usr/bin/id $ sudo grep "incorrect password" /var/log/secure # wrong sudo passwords $ sudo grep "COMMAND=" /var/log/secure | tail -3 # everything people ran with sudo $ sudo journalctl _COMM=sudo --since today # same information from the journal
Part of the log lineMeaning

9.5 Manage Local User Accounts

Creating users: useradd (and adduser)

On RHEL, adduser is just another name (a symbolic link) for useradd. They are the same command.

$ ls -l /usr/sbin/adduser lrwxrwxrwx. 1 root root 7 ... /usr/sbin/adduser -> useradd

Syntax: useradd [options] username. On success it prints nothing. Silence means success.

$ sudo useradd john # simplest form $ grep john /etc/passwd john:x:1000:1000::/home/john:/bin/bash

What useradd did automatically: picked the next free UID (1000), created the private group john, created /home/john and copied starter files from /etc/skel. The comment field is empty (the :: after 1000). No password is set, so john cannot log in until you run passwd.

OptionMeaning
-u 2000Choose the UID yourself
-g group / -G listPrimary group / secondary groups (comma separated)
-c "text"Comment (full name)
-d /pathHome folder location
-m / -MCreate / do not create the home folder
-s /bin/shLogin shell
-rMake a system account (number from the 1–999 range)
-e 2026-12-31Account expiry date

Example A: choose the UID and the shell

$ sudo adduser -u 2000 -s /bin/sh user1 $ grep user1 /etc/passwd user1:x:2000:2000::/home/user1:/bin/sh $ id user1 uid=2000(user1) gid=2000(user1) groups=2000(user1)

Reading it: UID is 2000 (our choice, it is inside the regular range), the private group also got 2000, and the shell is /bin/sh instead of bash.

Example B: a system account with a chosen UID

$ sudo adduser -r -u 888 user2 $ id user2 uid=888(user2) gid=888(user2) groups=888(user2) $ ls -ld /home/user2 ls: cannot access '/home/user2': No such file or directory

-r says "system account", so the number must come from the 1–999 range. -u 888 asks for 888 specifically, and it works only if 888 is free (check with getent passwd 888; empty output = free). If it is taken you get UID 888 is not unique. System accounts get no home folder by default (add -m if you want one).

Set the password: passwd

$ sudo passwd john New password: Retype new password: passwd: all authentication tokens updated successfully.

You type the password twice (nothing appears on the screen). The last line means success. If you are root and choose a weak password, you only get a BAD PASSWORD warning and it is still accepted. A regular user changing their own password must follow the quality rules (not too short, not a dictionary word, not their username). Run passwd with no name to change your own password.

Modifying users: usermod

usermod changes the properties of an existing user. Syntax: usermod [options] username

-mMove the old home contents (use together with -d)usermod -m -d /home/newjohn john

$ sudo usermod -c "John Smith" john $ sudo usermod -s /bin/sh john $ grep john /etc/passwd john:x:1000:1000:John Smith:/home/john:/bin/sh # field 5 and field 7 changed $ sudo usermod -u 3000 john $ id john uid=3000(john) gid=1000(john) groups=1000(john)
⚠️ Two traps
• usermod -G devs john without -a replaces all of john's secondary groups with only devs. Always write -aG.
• After usermod -u, only john's home folder files are updated to the new number. Files elsewhere keep the old UID and become "orphans". Find them with sudo find / -uid 1000 2>/dev/null and fix them with chown. Do not change a UID while the user is logged in.

Change versus move the home directory

When and why do you need this?

  • The /home disk is full, so you want the user's files on a bigger disk (for example /data/john).
  • Company rule: all homes must be under a certain path.
  • The user was created without a home folder (-M or -r) and now needs one.
  • You renamed a user and want the folder name to match.
Change = update the address only. Move = update the address and carry the belongings.

Option 1: change only (new, empty home)

$ sudo mkdir /home/newjohn # 1. the folder must exist first $ sudo chown john:john /home/newjohn # 2. make john (user:group) its owner $ sudo chmod 700 /home/newjohn # 3. only john may enter (private) $ sudo usermod -d /home/newjohn john # 4. update /etc/passwd $ grep john /etc/passwd john:x:1000:1000:John Smith:/home/newjohn:/bin/bash # field 6 changed

Careful: chown user:group folder only sets the owner, and usermod -d alone only changes the path. Neither of them copies anything. If you also want the old files in the new folder, copy them yourself and keep owners and permissions with -a:

$ sudo cp -a /home/john/. /home/newjohn/ # "." copies hidden files too

Option 2: move (one command does it all)

$ sudo usermod -m -d /home/newjohn john $ ls -ld /home/newjohn drwx------. 5 john john 138 Oct 24 11:02 /home/newjohn $ ls -ld /home/john ls: cannot access '/home/john': No such file or directory

The path after -d is always the new location. -m works only together with -d. The old folder is gone and the owner (john john) is kept. The user should be logged out while you do this.

usermod -d (change)usermod -m -d (move)

Lock and unlock an account

$ sudo usermod -L john # Lock the password $ sudo passwd -S john # -S = Status john LK 2026-10-24 0 99999 7 -1 (Password locked.) $ sudo usermod -U john # Unlock $ sudo passwd -S john john PS 2026-10-24 0 99999 7 -1 (Password set, SHA512 crypt.)

How to read passwd -S

1 · NamejohnThe account
2 · StatusLK / PS / NPLK = locked · PS = password set and usable · NP = no password
3 · Last change2026-10-24Date the password was last changed
4 · Min days0Days before it may be changed again
5 · Max days99999Days until it expires
6 · Warn days7Days of warning before expiry
7 · Inactive-1-1 = never locked after expiry

How locking works: it adds an exclamation mark ! in front of the password hash in /etc/shadow. Now no typed password can ever match.

$ sudo grep john /etc/shadow john:$6$Xk2...Qz9:20750:0:99999:7::: # before: normal hash john:!$6$Xk2...Qz9:20750:0:99999:7::: # after usermod -L: "!" added
⚠️ A lock does NOT stop root or sudo users
Locking only blocks password logins. Root (or anyone with sudo) can still become the locked user, because root never needs the user's password:
$ sudo su - john # works even though john is locked $ sudo -u john id # works too
Also, the user can still log in with an SSH key. To block everything, lock and expire the account: sudo usermod -L -e 1 john (or sudo chage -E 0 john), and optionally give the nologin shell.

Deleting users: userdel

$ sudo userdel user1 # removes the account, KEEPS the home folder $ sudo userdel -r alice # removes the account AND home folder AND mail spool $ ls -l /home drwx------. 3 1001 1001 78 Oct 24 11:30 user1

Look at the last line: after userdel user1 (no -r) the folder /home/user1 is still there, but the owner is shown as plain numbers (1001 1001) because the name no longer exists. These are orphaned files. If a new user later receives the same UID 1001, they would own the old files. Safer habits:

  • Use userdel -r to remove everything, or
  • Find leftovers: sudo find / -nouser 2>/dev/null (files with no owner).
  • A logged-in user cannot be deleted: userdel: user john is currently used by process 2301. Log them out first (or use -f to force).
  • If unsure, lock the account instead of deleting it.

The nologin shell

The login shell (field 7 of /etc/passwd) is the program that starts when someone logs in. /sbin/nologin is a "fake shell" that does nothing except print a polite refusal and exit. It is for accounts that must exist (a program uses them) but must not give a command prompt to a person.

$ sudo usermod -s /sbin/nologin user1 $ grep user1 /etc/passwd user1:x:2000:2000::/home/user1:/sbin/nologin $ su - user1 This account is currently not available. $ grep -c nologin /etc/passwd # how many accounts have no login? 32

9.7 Manage Local Group Accounts

Creating, changing and deleting groups

CommandWhat it does
groupadd devsCreate a group. The GID is the next free number
groupadd -g 10000 devsCreate a group with a chosen GID

$ sudo groupadd -g 10000 devs $ getent group devs devs:x:10000: # empty at the end = no members yet $ sudo groupmod -n team devs $ getent group team team:x:10000: # same GID, new name $ sudo groupdel team
⚠️ You cannot delete a user's primary group
$ sudo groupdel john groupdel: cannot remove the primary group of user 'john'
Delete the user first, or change that user's primary group. Also check for files that belong to the group: sudo find / -group devs 2>/dev/null.

Group membership

Add a user to a secondary group

$ sudo usermod -aG devs john $ id john uid=1000(john) gid=1000(john) groups=1000(john),10000(devs) $ getent group devs devs:x:10000:john

Reading: john's primary group is still john (1000). devs (10000) was added to his list. In /etc/group, the 4th field of devs now lists john.

usermod -aG also takes several groups at once: sudo usermod -aG devs,wheel john. The user must log out and log in again before the new group applies to their current session.

Remove a user from a group

$ sudo gpasswd -d john devs Removing user john from group devs $ id john uid=1000(john) gid=1000(john) groups=1000(john)
📝 Mind the order
The syntax is gpasswd -d user group (user first, then group). Related: gpasswd -a john devs adds a user, and gpasswd -M john,alice devs sets the whole member list.

Change the primary group

$ sudo usermod -g devs john $ id john uid=1000(john) gid=10000(devs) groups=10000(devs)

Now gid shows devs, so new files created by john will belong to the group devs. (John's groups list changed too, because the old private group is no longer in it.)

Use another group only for now: newgrp

A user can switch the primary group of the current shell, but only to a group they already belong to. It lasts until exit.

$ newgrp devs $ id uid=1000(john) gid=10000(devs) groups=10000(devs),1000(john) $ exit

9.9 Manage User Passwords

Where passwords live: /etc/shadow

A password is never stored as typed. Linux stores a hash: a scrambled version that cannot be turned back into the password. At login, the system hashes what you typed and compares the two. The file is /etc/shadow, readable only by root.

$ sudo grep john /etc/shadow john:$6$Xk2aB9qL$Hw8...Qz9:20750:0:99999:7:::

Nine fields, separated by colons. Fields 3 to 8 are the aging properties:

1 · NamejohnUsername
2 · Hash$6$Xk2…Qz9The scrambled password. ! in front = locked. !! or * = no password
3 · Last change20750Days since 1 Jan 1970 when the password was last set
4 · Minimum0Days you must wait before changing it again. 0 = any time
5 · Maximum99999Days the password stays valid. 99999 = never expires
6 · Warning7Days of warning before it expires
7 · Inactive(empty)Days after expiry until the account is locked. Empty = never
8 · Expire(empty)Day number when the whole account dies. Empty = never
9 · Reserved(empty)Not used

The hash itself: $6$Xk2aB9qL$Hw8…

PartMeaning
$6$The algorithm: 1 = MD5 (old, weak), 5 = SHA-256, 6 = SHA-512 (the RHEL default)
Xk2aB9qLThe salt: random text added before hashing, so two users with the same password still have different hashes
the restThe hash value

Why "days since 1970"? Reading field 3

Computers need one starting point to count time. For Unix and Linux this "time zero" is 1 January 1970 (called the Unix epoch). Many fields in /etc/shadow are simply "number of days after that day". The number 20750 means "20750 days after 1 Jan 1970". Convert it to a normal date with:

$ date -d "1970-01-01 +20750 days" +%F 2026-10-24 $ echo $(( $(date +%s) / 86400 )) # today as a day number 20750

So john's password was last set on 24 October 2026. The other way round (date to number) is the second command: seconds since 1970 divided by 86400 seconds per day.

Password aging: the chage command

chage means change age. It shows and changes the aging properties of an account (the fields 3 to 8 above). Aging forces people to change passwords regularly.

The life of a password: from the day it is set until the account is locked.

chage options

OptionMeaningExample
-lList the current settingschage -l john
-m daysMinimum days between changeschage -m 2 user1
-M daysMaximum days a password is validchage -M 30 user1
-W daysWarning days before expirychage -W 5 user1
-I daysInactive days after expiry, then the account is lockedchage -I 10 user1
-E dateAccount Expiry date (YYYY-MM-DD). -1 = neverchage -E "2026-12-31" user1
-d 0Set the "last changed" day to 0: force a new password at next loginchage -d 0 user1

Small letter -m = minimum, capital -M = maximum. Remember: capital = bigger.

How to read chage -l

$ sudo chage -m 5 -M 30 -I 10 -W 5 user2 # set everything in one command $ sudo chage -l user2 Last password change : Oct 24, 2026 Password expires : Nov 23, 2026 Password inactive : Dec 03, 2026 Account expires : never Minimum number of days between password change : 5 Maximum number of days between password change : 30 Number of days of warning before password expires : 5
LineMeaning here
Last password changeThe day the password was set (today)
Password expiresLast change + 30 days (-M) = Nov 23
Password inactiveExpiry + 10 days (-I) = Dec 03. After this date the account is locked
Account expiresThe -E date. "never" because none was set
Minimum / MaximumThe -m (5) and -M (30) values
WarningThe -W value: warn 5 days before Nov 23

Before any change a fresh account shows never for expiry, minimum 0, maximum 99999, warning 7. Those are the defaults from /etc/login.defs, and also what you see in /etc/shadow fields 4–6.

After the password expires, does it still work?

Yes, one more time. When the maximum age is reached, the old password is still accepted, but the system forces the user to choose a new one right away. If they ignore this for a long time, nothing happens by default (the account is not locked). The -I option adds the deadline:

$ sudo chage -I 10 user1 # 10 days after expiry, user1 is locked out completely
  • Day 0 to 10 after expiry: login works, new password is required.
  • After day 10: the account is locked. The user cannot log in or change the password. Only an administrator can fix it.

Account expiry and forced change

$ sudo chage -E "2026-12-31" user1 # the account dies on 31 Dec 2026 $ sudo chage -l user1 | grep "Account expires" Account expires : Dec 31, 2026 $ sudo chage -E -1 user1 # remove the expiry date $ sudo chage -d 0 user1 # force a new password at next login $ sudo chage -l user1 | head -1 Last password change : password must be changed $ su - user1 Password: You are required to change your password immediately (administrator enforced). Changing password for user user1. New password:
📝 Do not mix these up
-M = how long the password lasts. -E = when the whole account ends. -d 0 = "change your password right now". Aging only affects people who log in with passwords; changing the settings of /etc/login.defs only affects new users, so use chage for existing ones.

Password policy

  • Aging rules (how long): /etc/login.defs for new users, chage for existing users.
  • Quality rules (how strong): /etc/security/pwquality.conf sets the minimum length and the kinds of characters a regular user must use. Root can override them with a warning.

How to check failed login attempts

CommandShows
sudo lastbList of bad (failed) login attempts

$ sudo lastb | head -3 john ssh:notty 192.168.1.50 Sat Oct 24 10:15 - 10:15 (00:00) alice pts/1 Sat Oct 24 10:12 - 10:12 (00:00) btmp begins Thu Oct 22 08:01:44 2026 $ sudo faillock --user john john: When Type Source Valid 2026-10-24 10:15:03 RHOST 192.168.1.50 V 2026-10-24 10:15:09 RHOST 192.168.1.50 V $ sudo faillock --user john --reset # clear the counter (unlocks a user blocked by too many failures)
Part (lastb)Meaning

In the faillock table, each row is one failed try. V means the failure is still valid (it counts toward the lockout limit). Once the limit is reached, the user is blocked for a while. --reset clears the rows.
