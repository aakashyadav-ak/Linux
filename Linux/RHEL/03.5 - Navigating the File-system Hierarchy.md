# 6.1 The Linux file-system hierarchy

## What is it?
- Linux stores **all files** in one **inverted tree**: the root is at the top, and branches go down.
- The top is the **root directory**, written `/`.
- `/` is also the **separator** between folder names: `/etc/issue` = file `issue` inside `etc` inside `/`.
- Subdirectories have standard purposes, so files are easy to find. Example: `/boot` holds boot files.
- Directory = folder. Both words mean the same.

## Tree (simplified)
```
/
├── boot
├── dev
├── etc
├── home
│   ├── alice
│   ├── bob
│   └── eve
├── root
├── run
├── tmp
├── usr
│   ├── bin
│   ├── sbin
│   └── local
├── var
├── bin   -> usr/bin     (link)
├── sbin  -> usr/sbin    (link)
├── lib   -> usr/lib     (link)
└── lib64 -> usr/lib64   (link)
```

> [!warning] Trap: `/` vs `/root` vs `/home/root`
> - `/` = the **root directory** (top of everything).
> - `/root` = the **home directory of the root user**.
> - `/home/root` does **not** exist as the root user's home. This is a quiz trick.

## Terms used to describe contents (book)
| Term                   | Meaning                                                |
| ---------------------- | ------------------------------------------------------ |
| **Static**             | Does not change until someone edits or reconfigures it |
| **Dynamic / variable** | Can be changed or appended to by running processes     |
| **Persistent**         | Stays after a reboot (config settings)                 |
| **Runtime**            | Deleted on reboot                                      |

## Important directories (book, Table 10)
| Location   | Purpose                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------- |
| `/boot`    | Files to start the boot process (kernel, initramfs, GRUB)                                               |
| `/dev`     | Special **device files** used to access hardware                                                        |
| `/etc`     | **System-specific configuration** files                                                                 |
| `/home`    | Home directories of **regular users** (data and settings)                                               |
| `/root`    | Home directory of the **root** (superuser)                                                              |
| `/run`     | **Runtime** data of processes started since the last boot (PID files, lock files). Re-created on reboot |
| `/tmp`     | **Temporary** files, writable by everyone. Files not used for **10 days** are deleted automatically     |
| `/var/tmp` | Also temporary. Files not used for **30 days** are deleted automatically                                |
| `/usr`     | Installed **software**, shared libraries, read-only program data                                        |
| `/var`     | **Variable data** that must survive reboots: databases, caches, **logs**, print spool, website content  |

### Subdirectories of `/usr` (book)
| Path | Purpose |
|---|---|
| `/usr/bin` | **User commands** |
| `/usr/sbin` | **System administration** commands |
| `/usr/local` | Software you install or customize yourself |

> [!note] `/run` replaced two old folders
> `/run` combines the old `/var/run` and `/var/lock` from earlier RHEL versions.

## Important: merged directories (book)
In RHEL 7 and later, these four root-level folders are **symbolic links** (shortcuts) to the matching folders in `/usr`:

| Link | Points to |
|---|---|
| `/bin` | `/usr/bin` |
| `/sbin` | `/usr/sbin` |
| `/lib` | `/usr/lib` |
| `/lib64` | `/usr/lib64` |

Earlier RHEL versions kept these as separate folders with different files.

```bash
ls -ld /bin /sbin /lib /lib64     # (extra) the "l" at the start and "->" show they are links
```

## Extra directories you will meet soon (extra)
| Location    | Purpose                                                                   |
| ----------- | ------------------------------------------------------------------------- |
| `/proc`     | **Virtual** files showing running processes and kernel info (not on disk) |
| `/sys`      | **Virtual** files showing hardware and drivers                            |
| `/mnt`      | Place to mount a disk **temporarily** by hand                             |
| `/media`    | Where removable media (USB, DVD) is auto-mounted (Chapter 14)             |
| `/opt`      | Optional third-party software                                             |
| `/srv`      | Data served by this system (web, FTP)                                     |
| `/boot/efi` | UEFI boot files (only on UEFI systems)                                    |

- Man page for the full list: `man 7 hier`
- Why installers let you make `/boot`, `/home` and `/var` separate partitions: their contents have different jobs, and a full `/var` (logs) then cannot fill `/`.

# 6.1.1 `/usr/bin` vs `/usr/sbin` (your question)

| | `/usr/bin` | `/usr/sbin` |
|---|---|---|
| **Name** | **bin** = binaries (programs) | **sbin** = **s**ystem **bin**aries |
| **For** | Everyday **user commands** | **System administration** commands |
| **Examples** | `ls`, `cat`, `cp`, `grep`, `passwd`, `ssh` | `fdisk`, `useradd`, `usermod`, `mkfs.xfs`, `fsck`, `sshd`, `shutdown` |
| **Used by** | Everyone | Mainly the admin (root or `sudo`) |

> [!tip] Memory trick
> **bin** = "things I use." **sbin** = "things the **s**ystem **admin** uses."

> [!warning] Common wrong idea (extra)
> The folder does **not** decide who can run a command. **File permissions** do.
> - Some `/usr/sbin` programs work fine for a regular user, for example `ip a`.
> - Some commands in `/usr/bin` need root to do certain things.
> - `sbin` is a **hint** that the command is meant for admins and usually needs root.

### Where does the shell look? (PATH) (extra)
```bash
echo $PATH         # list of folders the shell searches for commands
which fdisk        # shows the full path, usually /usr/sbin/fdisk
type -a ls         # (extra) shows every match
```
- On RHEL, the `sbin` folders are normally in a regular user's `PATH` as well, but near the end. Check with `echo $PATH` on your VM.
- If a command is "not found" but exists, run it with the full path: `/usr/sbin/fdisk -l`.

### Other related locations
| Path | Purpose |
|---|---|
| `/usr/local/bin` | Your own or locally installed programs |
| `/usr/local/sbin` | Your own admin programs |

> [!note] Future change (extra, verify)
> Newer Fedora releases have started merging `/usr/sbin` into `/usr/bin`. Your RHEL 10 book still lists them separately, so **learn them separately for the exam**.

# 6.1.2 Why can't a regular user run `fdisk`, but root can? (your question)

## Short answer
`fdisk` has to **open the raw disk** (`/dev/sda`) to read or change the partition table. Only root, and members of the `disk` group, are allowed to open that device file. A regular user gets **Permission denied**.

## Step by step
1. `fdisk` lives in `/usr/sbin/fdisk`. It manages **disk partitions**.
2. To do its job it opens a **device file** such as `/dev/sda`.
3. Device files have permissions like any other file:
```bash
   ls -l /dev/sda
   brw-rw----. 1 root disk 8, 0 Oct 11 10:02 /dev/sda
```
   | Part | Meaning |
   |---|---|
   | `b` | Block device (a disk) |
   | `rw-` (owner) | Owner `root` can read and write |
   | `rw-` (group) | Group `disk` can read and write |
   | `---` (others) | Everyone else: **no access** |
4. A regular user is not the owner and not in the `disk` group, so they are in "others" and have **no access**.
5. **Root** (UID 0) has full privileges, so the kernel lets root open and change any file or device.

```bash
# As a regular user
fdisk -l
# fdisk: cannot open /dev/sda: Permission denied

# With sudo
sudo fdisk -l           # works, lists the partitions

# As root
fdisk -l                # works
```
(The disk name may be `/dev/sda`, `/dev/vda` or `/dev/nvme0n1` on your VM.)

## Why is it designed this way?
- Changing a partition table can **destroy all data** on a disk.
- Protecting raw disk access stops normal users and their programs from damaging the system.
- This is the **least privilege** rule: give only the power that is needed.

## Practical advice (extra)
- Use `sudo fdisk -l` to **look** at disks. It only reads and changes nothing.
- `sudo fdisk /dev/sda` opens an interactive menu. Nothing changes until you press `w` (write). Press `q` to quit **without saving**.
- Do **not** add a user to the `disk` group just to avoid `sudo`. It gives that user raw access to the whole disk.
- A regular user **can** run `lsblk`, which lists disks and partitions without needing root.

> [!tip] Rule to remember
> Command **found** in the path, but still **Permission denied**? Then it is a **permissions problem**, not a missing command.

# 6.3 Specifying files by name

## Paths
- A **path** is the unique location of a file or directory. Folder names are separated by `/`.
- Directories are written the same way as files.

> [!warning] Spaces in file names (book)
> A space is **allowed** in a Linux file name, but the shell treats spaces as **separators between arguments**.
> If a name has a space, put it in **quotes**: `touch "my file.txt"`. Red Hat recommends **avoiding spaces** completely.

## Absolute path
- Starts with `/` and gives the **complete** route from the root.
- Works from **anywhere**. Every file has exactly one absolute path.
- Example: `/var/log/messages`

> [!tip] Rule
> First character is `/` → **absolute**.

## Relative path
- Starts with **anything except `/`**.
- Describes the route from your **current working directory**.
- Example: if you are in `/var`, the same file is `log/messages`.
- A name with **no slash** means a file in the current directory.

> [!tip] Rule
> First character is **not** `/` → **relative**.

| | Absolute | Relative |
|---|---|---|
| Starts with | `/` | Anything else (`log/`, `../`, `./`, `file`) |
| Depends on where you are? | No | Yes |
| Example from `/home/user` | `/home/user/Documents` | `Documents` |
| Length | Longer | Shorter |

## Case sensitivity (book)
- Linux file systems (**ext4, XFS**) are **case-sensitive**.
  `MyExample.txt` and `myexample.txt` are **two different files**.
- **VFAT, NTFS, Apple HFS+ and APFS** are **case-preserving**: they show your capital letters but treat both names as the **same** file.

## The current working directory
- The place your shell is "standing" right now. When you log in, it is your **home directory**.
- `pwd` = print the full path of the working directory.
- The prompt shows:
  - `~` when you are **in your home directory**.
  - `~/Videos` when you are inside a folder in home.
  - The **full path** (like `/var/log`) when you are outside home.

```bash
user@host:~$ pwd
/home/user
user@host:~$ ls
Desktop  Documents  Downloads  Music  Pictures  Public  Templates  Videos
```

## `cd`: change directory
```bash
cd Videos                  # relative path
cd /home/user/Documents    # absolute path
cd                         # no argument = go home
cd -                       # go to the previous directory (jump back and forth)
cd ..                      # go up one level (parent)
cd ../..                   # go up two levels
cd .                       # stay in the current directory
```
- `cd` with no argument always returns you to **your own home** directory.
- `cd -` swaps between two directories. Very useful when working in two places.

### Example from the book
```bash
user@host:~$ cd Videos
user@host:~/Videos$ cd /home/user/Documents
user@host:~/Documents$ cd -
user@host:~/Videos$ cd -
user@host:~/Documents$
```

## `touch`: create practice files
- Updates a file's time stamp to now **without changing the content**.
- If the file **does not exist**, it **creates an empty file**.
```bash
touch Videos/blockbuster1.ogg
touch Documents/thesis_chapter1.txt
touch ~/helloworld.py
touch file{1..10}           # (extra) makes file1 to file10 (brace expansion, Chapter 7)
```

## `ls`: list directory contents
| Option | Meaning |
|---|---|
| `ls` | Names only (hidden files not shown) |
| `ls -l` | **Long** format with details |
| `ls -a` | **All** files, including hidden ones |
| `ls -R` | **Recursive**, includes everything in subfolders |
| `ls -la` or `ls -al` | Long format **and** hidden files (same result) |
| `ls -l ~` | Long listing of your home, from anywhere |

### Reading `ls -l` output (extra)
```
drwxr-xr-x. 2 user user 6 Mar 2 02:45 Documents
```
| Part | Meaning |
|---|---|
| `d` | Type: `d` directory, `-` regular file, `l` link, `b` block device |
| `rwxr-xr-x` | Permissions (owner / group / others). See Chapter 11 |
| `.` | An **SELinux** security label exists (RHEL feature) |
| `2` | Number of links |
| `user user` | Owner and group |
| `6` | Size in bytes |
| `Mar 2 02:45` | Last modified |
| `Documents` | Name |

## Special directories `.` and `..`
- They exist in **every** directory.
  - `.` = the **current** directory
  - `..` = the **parent** (one level up)
- They appear at the top of `ls -la`.
- `.` is useful as a source or destination, for example `cp /etc/hosts .` (copy to here).

```bash
user@host:~/Videos$ cd ..
user@host:~$ cd ..
user@host:/home$ cd ..
user@host:/$ cd
user@host:~$
```

## Hidden files (book)
- Any name that **starts with a dot** (`.bashrc`, `.bash_history`, `.config`) is **hidden**.
- Hidden files do **not** show in plain `ls`. Use `ls -a`.
- > [!warning] Hidden is NOT secure
> Hiding is only to **keep home directories tidy** and to stop one user's settings from being copied by accident.
> To protect file **contents**, use **file permissions** (Chapter 11).

## The `~` (tilde) shortcut
```bash
cd /var/log
ls -l ~            # lists your home directory from anywhere
touch ~/test.txt   # creates a file in your home from anywhere
```
- `~` = your home directory. `~user2` = home of another user (extra).
- Do not confuse `~` (home) with `~tmp`, which means "home of a user named tmp", not `/tmp`.

# 6.5 Summary (book, in simple words)
- Linux keeps all files in **one inverted tree** called the file-system hierarchy.
- Each folder under `/` has a **purpose**: `/boot` for boot files, `/etc` for configuration.
- Files are **case-sensitive**. Point to them with an **absolute** path (starts with `/`) or a **relative** path.
- `cd` changes directory. `.` is the current directory and `..` is the parent.
- `ls` hides **hidden files** by default. Any name starting with `.` is hidden.
