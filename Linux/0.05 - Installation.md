# RHEL 10 Install Notes (VMware) - Beginner Guide

> [!info] How to use this note
> The sections follow the **real installation order**. Read top to bottom while you install.

---

## Part 1: Before You Install (Basic Concepts)

### 1.1 What happens when a computer starts?
`Power on → Firmware (BIOS/UEFI) → Bootloader (GRUB) → Kernel → systemd → Login`

| Step | What it does (simple words) |
|---|---|
| **Firmware (BIOS/UEFI)** | The first program that runs. It checks the hardware (called POST) and finds a disk to boot from. |
| **GRUB** | The bootloader. It shows the boot menu and loads the kernel. |
| **Kernel** | The core of Linux. It talks to the hardware. |
| **initramfs** | A tiny temporary filesystem that helps the kernel find your real disk. |
| **systemd** | Starts all services and brings up the login screen. |

### 1.2 BIOS types: Legacy vs UEFI vs EFI
- **Legacy BIOS**: the old firmware. It boots from the **MBR** (first sector of the disk).
- **UEFI**: the modern firmware. It boots from a special **EFI partition** and uses **GPT** disks.
- **EFI**: the older name of UEFI. People often say "EFI" and "UEFI" to mean the same thing.
- In VMware, change this under: VM Settings → Options → Advanced → **Firmware type**.
- **Tip:** use **UEFI** for new installs, since it is the modern standard.

### 1.3 EROM (ROM / EEPROM chip)

> [!info] Simple meaning
> A small chip on the motherboard that stores the **BIOS/UEFI firmware**. It keeps its data even when the power is off.

**ROM types (oldest to newest)**

| Type | Full name | Can it be changed? |
|---|---|---|
| **ROM** | Read-Only Memory | No, fixed at the factory |
| **PROM** | Programmable ROM | Written once |
| **EPROM** | Erasable PROM | Erased with UV light, then rewritten |
| **EEPROM** | Electrically Erasable PROM | Erased and rewritten **with electricity**, no removal needed |
| **Flash** | A modern kind of EEPROM | Used on today's motherboards |

**Why it matters**
- When you power on, the CPU first runs the program stored on this chip (BIOS/UEFI).
- That program does **POST** (hardware self-test), then hands control to **GRUB**.
- Updating the BIOS is called **"flashing"**, because you rewrite this chip.

**Don't confuse with CMOS**
- **ROM/EEPROM**: stores the firmware program itself.
- **CMOS**: tiny memory that stores *settings* (clock, boot order). It is kept alive by the small coin battery on the motherboard.

**In VMware**
- The VM has a *virtual* firmware chip, so there is no physical ROM.
- Its settings are saved in the VM's **`.nvram`** file. If the VM's boot settings get messed up, deleting that file resets them.
- Firmware type (BIOS or UEFI) is chosen under VM Settings → Options → Advanced.

## Part 2: VMware Setup

### 2.1 Create the VM
1. New Virtual Machine → choose **Installer disc image file (ISO)**.
2. Guest OS: **Linux → Red Hat Enterprise Linux 10 64-bit** (or the closest version listed).
3. Set CPU, RAM and disk size (lab suggestion: 2 CPU, 4 GB RAM, 30 GB disk).
4. Choose a network mode (see below).

> [!warning] RHEL 10 CPU requirement
> RHEL 10 needs a CPU with **x86-64-v3** support. If the VM fails to boot with a CPU error, use a newer VMware hardware version or a newer host machine.

### 2.2 Network types in VMware
| Mode | Simple meaning | Internet? | Use case |
|---|---|---|---|
| **NAT** | VM hides behind your PC's IP, like many phones sharing one home router. | Yes | Default and easiest. |
| **Bridged** | VM becomes a separate device on your real network and gets its own IP from your router. | Yes | When other devices must reach the VM. |
| **Host-only** | A private network only between your PC and the VMs. | No | Isolated lab. |

(I read "host sharing" as **Host-only**.)

## Part 3: Boot Menu of the Installer

When the ISO boots, you see a menu. This menu is **GRUB**.

| Option | What it does |
|---|---|
| **Install Red Hat Enterprise Linux 10** | Starts the installation. |
| **Test this media & install** | Checks the ISO for corruption, then installs. |
| **Troubleshooting** | Opens repair options (see below). |

### 3.1 Test this media
- It runs a **checksum** on the ISO to find a bad download or a bad burn.
- Takes a few minutes.
- Useful on real hardware, and you can skip it for a trusted ISO in a lab.

### 3.2 Troubleshooting option
- **Install in basic graphics mode**: use it if the screen is black or broken.
- **Rescue a Red Hat Enterprise Linux system**: boots a repair environment. Your installed system is mounted at `/mnt/sysimage`.
```bash
  chroot /mnt/sysimage
```
  `chroot` means "pretend this folder is the root of the system", so you can fix things as if you had booted normally.
- **Boot from local drive**: skips the installer and boots the installed OS.
- **Memory test**: tests RAM (on UEFI systems).

### 3.3 GRUB basics
- At any GRUB menu:
  - `e` = **edit** the selected entry (temporary, lost after reboot)
  - `c` = open the **GRUB command line**
  - `Ctrl+x` = boot with your edits
- On the installed system:
  - Main settings file: `/etc/default/grub`
  - Generated config: `/boot/grub2/grub.cfg` (BIOS) or `/boot/efi/EFI/redhat/grub.cfg` (UEFI)
  - Apply changes: `grub2-mkconfig -o /boot/grub2/grub.cfg`
- RHCSA skill: reset a lost root password by adding `rd.break` to the kernel line.

## Part 4: Installer Screens (Anaconda)

The installer is called **Anaconda**. The main screen is a hub of options.

| Screen | Meaning |
|---|---|
| Language / Keyboard | Your language and keyboard layout |
| Time & Date | Timezone |
| **Installation Source** | Where packages come from (local ISO or network) |
| **Software Selection** | What to install (see below) |
| **Installation Destination** | Which disk and how to partition it |
| **KDUMP** | Crash dump setting |
| **Network & Host Name** | IP and hostname |
| **Security Profile** | Optional compliance rules (OpenSCAP) |
| **Root Password** | Admin account |
| **User Creation** | Your normal user |

### 4.1 Software Selection
- **Server with GUI**: server plus a desktop. Best for beginners.
- **Server**: no desktop, command line only.
- **Minimal Install**: bare minimum, so you add everything yourself.
- **Workstation**: desktop for daily use.

> [!tip] For learning RHCSA
> Use **Server with GUI** first. Move to **Server** or **Minimal** later to practice the command line.

## Part 5: Installation Destination (the big one)

### 5.1 Automatic vs Custom
| | Automatic | Custom |
|---|---|---|
| Who decides the layout | Installer | You |
| Difficulty | Easy | Needs knowledge |
| Best for | Quick lab | **Learning and exams** |

### 5.2 What is a partition?
Splitting one physical disk into separate sections. Think of one big cupboard divided into shelves, where each shelf has its own purpose.

### 5.3 Partition table types
| Type | Used with | Limits |
|---|---|---|
| **MBR** | Legacy BIOS | 2 TB max, 4 primary partitions |
| **GPT** | UEFI | Very large disks, 128 partitions |

### 5.4 Device types
- **Standard Partition**: fixed-size partitions. Simple, but hard to resize.
- **LVM** (Logical Volume Manager): flexible storage. You can grow volumes later without reinstalling.
- **LVM Thin Provisioning**: space is allocated only when used.
- **Software RAID**: combines several disks for speed or safety.

> [!tip] What is LVM?
> Imagine disks as water tanks (**PV**), joined into one big pool (**VG**), from which you take portions (**LV**) of any size. You can add a bigger portion later.
> `Disk → PV (Physical Volume) → VG (Volume Group) → LV (Logical Volume)`

### 5.5 Custom layout with LVM
| Mount point | Purpose | Size (lab) | Notes |
|---|---|---|---|
| `/boot` | Kernel, initramfs and GRUB files | 1 GiB | Stays **outside LVM**, xfs |
| `/boot/efi` | EFI boot files | 600 MiB | **UEFI only**, vfat |
| `biosboot` | Boot code for BIOS + GPT | 1 MiB | **BIOS + GPT only** |
| `/` | Root, everything else | 15-20 GiB | xfs, inside LVM |
| `swap` | Virtual memory (disk used as extra RAM when RAM is full) | 2-4 GiB | |
| `/home` | Users' files | optional | Survives a reinstall of `/` |
| `/var` | Logs, caches, spool | optional | A growing log cannot fill `/` |

> [!note] Why separate `/home` and `/var`?
> If logs grow too large they can fill the disk and crash the system. A separate partition limits the damage and keeps user data safe.

### 5.6 File system types
| Type | Notes |
|---|---|
| **XFS** | **RHEL default**. Fast. Can grow, **cannot shrink**. |
| **ext4** | Can grow and shrink. |
| **vfat** | Used for `/boot/efi`. |
| **swap** | Virtual memory. |
| **NFS** | Network file system. |
| **iso9660** | CD/DVD images. |
| Btrfs | **Not supported** in RHEL. |

### 5.7 Disk names in Linux
- `/dev/sda`: SATA/SCSI disk (common in VMware)
- `/dev/vda`: virtio disk (KVM)
- `/dev/nvme0n1`: NVMe disk
- Partitions get numbers: `/dev/sda1`, `/dev/sda2`

## Part 6: KDUMP

- **What:** when the kernel crashes (a "kernel panic"), a second small kernel starts and saves a memory snapshot called a **vmcore**. Experts use it to find the cause.
- **Cost:** it reserves some RAM all the time.
- **Dump location:** `/var/crash`
- **Config file:** `/etc/kdump.conf`
- **Commands:**
```bash
  systemctl enable --now kdump
  kdumpctl status
```
- In a small lab VM you can **disable it** during install to save RAM.

## Part 7: Network, Root and User

- **Network & Host Name:** turn the network **ON** and set a hostname such as `server1.example.com`.
- **Root password:** the admin (superuser) account.
- **User creation:** create a normal user and tick **Make this user administrator** so you can use `sudo`.

> [!warning] RHEL 10 change
> In RHEL 10, **root SSH login with a password is disabled by default**. Log in as your normal user and use `sudo`.

## Part 8: After Installation

### 8.1 Types of terminal
| Type | What it is | Example |
|---|---|---|
| **TTY** | Text-only virtual console | `Ctrl+Alt+F3` |
| **PTS** | Terminal window inside the GUI, or an SSH session | `/dev/pts/0` |
| **Serial console** | Console over a serial port, for servers without a screen | `ttyS0` |

- Check yours with the `tty` command.
- The **shell** (bash) is not the terminal. It is the program that runs inside the terminal and reads your commands.

### 8.2 Unattended install (Kickstart)
- A **Kickstart file** answers all installer questions automatically, which is useful for installing many servers.
- After any install, your choices are saved in `/root/anaconda-ks.cfg`. Use it as a template.
- Boot option: `inst.ks=http://server/ks.cfg`
- Storage lines in the file:
```
  clearpart --all --initlabel
  autopart --type=lvm
```
